# Internationalization

FsusBlog currently supports 10 UI locales: `zh-CN`（简体中文）、`zh-Hant`（繁體中文）、`en-US`、`ja-JP`、`ko-KR`、`fr-FR`、`de-DE`、`es-419`、`pt-BR`、`ru-RU`. Chinese (`zh-CN`) remains the catalog default. Public AOT resolves a request locale before renderer or cache lookup from canonical `fsusblog.locale` cookie, then `Accept-Language`, then `zh-CN`; the first HTML representation already uses that locale. Legacy `@/copy` constants are retired; all user-facing copy is centralized under `src/frontend/src/locales/`. `src/shared/Contracts/Localization/locale-catalog.json` is the only editable locale-code and metadata authority; its generated frontend and C# projections share a catalog digest. `bundleLoader.ts` is an independently checked consumer, not a registry. This document belongs to the **Localization and Public UX** capability phase; the legacy `v1.2.0` wording in issue #72 is not an active product version.

## Runtime contract

- `src/shared/Contracts/Localization/locale-catalog.json` owns locale codes, enabled state, aliases, document/Intl/OpenGraph metadata, names, direction, and script. It cannot contain frontend loaders or UI state.
- `tools/contracts/generate-locale-catalog.mjs` deterministically projects this catalog into frontend and C# generated surfaces; `--check` rejects digest drift.
- `src/frontend/src/locales/keys.ts` owns the storage key and derives exact supported identifiers plus typed leaf-key inference from the generated catalog and `zh-CN` schema.
- `src/frontend/src/locales/{zh-CN,zh-Hant,en-US,ja-JP,ko-KR,fr-FR,de-DE,es-419,pt-BR,ru-RU}/` contains matching, domain-oriented dictionaries (`common`, `public`, `article`, `auth`, `identity`, `layout`, `messages`, `security`, `admin`, `errors`). `zh-CN` is the single structure source and runtime fallback; all other locales are type-checked against `DeepStringShape<typeof zhCN>`.
- `src/frontend/src/locales/bundleLoader.ts` resolves and loads locale bundles by identifier; its map keys must exactly equal the catalog enabled set.
- `src/frontend/src/locales/index.ts` owns selection, persistence, document metadata, `Intl` date/number formatting, and exports structure & interpolation parity validators.
- `src/frontend/src/locales/validator.ts` implements structure parity, interpolation parameter matching, and placeholder checks.
- `useI18nText()` is the Vue integration boundary. UI code consumes typed `messages` or `t()` instead of hardcoding text or importing copy constants.

Missing keys or placeholder leaks never prevent rendering in production. Development and CI fail closed on missing typed keys, structure mismatch, parameter mismatch, or un-translated placeholders.

## Hydration and metadata

`ILocaleResolver` is a pure backend service. It accepts only an already validated explicit cookie locale, the raw `Accept-Language` value, and the catalog default; it does not access a database, authentication store, IP address, timezone, user agent, browser, Vue, or renderer. Header ranges use q/order semantics, ignore q=0 and invalid items, deduplicate ranges, apply catalog exact code/aliases plus BCP 47 parent lookup, and treat `*` as the catalog default. The result carries canonical locale, source, matched range, and catalog digest.

The resolved locale is immutable for one response. It selects the SSR domain bundle and visible copy, hydration `renderLocale`, `<html lang>` / `dir`, `Content-Language`, `og:locale`, `Intl` formatting, Public AOT cache key, and PublicHotRead HTML key. Contract validation rejects missing or divergent HTML/bootstrap/hydration locale before publication. Hydration loads that exact bundle before mounting and never reads `localStorage` to correct the server tree. `localStorage` remains client-only preference storage and is not server authority; the account/selector workflow that writes the canonical `fsusblog.locale` cookie is owned outside this server negotiation contract.

Public AOT date formatting is bound to the same render snapshot as locale negotiation. The backend supplies one canonical UTC `renderTimestamp` to the renderer, bootstrap, hydration, navigation snapshot, and backfill artifact; missing, blank, invalid, or noncanonical timestamps fail before SSR or seed consumption. Neither server nor browser may substitute a process clock, Unix epoch, `generatedAt` alias, or default locale for this authoritative value.

Public caches use only one of the ten canonical locale codes, never the raw header or account/user identity. HTML responses declare `Vary: Accept-Language, Cookie` (plus encoding where applicable) and `Content-Language`. To degrade all traffic to the default without restarting the application, an operator may temporarily normalize `Accept-Language` to `zh-CN` and strip only `fsusblog.locale` at the trusted edge; existing non-default entries remain bounded and may expire normally. Full code rollback is the previous application image and cache entries from the retired renderer version are rejected.

Locale changes update document/OpenGraph metadata from descriptor fields, never string replacement. Route titles use the same dictionary where a mapped title exists. Dates and numbers use `Intl.DateTimeFormat` and `Intl.NumberFormat` with the active descriptor's `intlLocale`; content bodies, article titles, user names, and other authored content are never machine-translated.

## Governance and validation

Legacy `@/copy` is retired. All translations match `zh-CN` structural keys 1:1 (`satisfies DeepStringShape<typeof zhCN>`). CI enforcement via `check-copy-centralization.mjs`, `validator.test.ts`, and `check:locale-catalog` guarantees fail-closed governance.

## Adding or changing copy

1. Add the `zh-CN` key in the relevant domain file.
2. Add structurally identical values in all supported locales; TypeScript rejects missing or extra branches (`satisfies DeepStringShape<typeof zhCN>`).
3. Consume it through `useI18nText()` and add a focused test for interactive or hydration-sensitive behavior.
4. Run `npm --prefix src/frontend run test:unit:fast -- ../../tests/frontend/unit/locales` and static check scripts.
