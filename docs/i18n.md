# Internationalization

FsusBlog currently supports `zh-CN` and `en-US` UI locales. Chinese remains the default and the public AOT shell language, while a visitor's explicit preference is applied after hydration and persisted in `localStorage`. Legacy `@/copy` constants are retired; all user-facing copy is centralized under `src/frontend/src/locales/`. This document belongs to the **Localization and Public UX** capability phase; the legacy `v1.2.0` wording in issue #72 is not an active product version.

## Runtime contract

- `src/frontend/src/locales/keys.ts` owns supported locale identifiers, the default, the storage key, and typed leaf-key inference.
- `src/frontend/src/locales/{zh-CN,en-US}/` contains matching, domain-oriented dictionaries (`common`, `public`, `article`, `auth`, `identity`, `layout`, `messages`, `security`, `admin`, `errors`). `zh-CN` is the single structure source and runtime fallback; `en-US` is type-checked against `DeepStringShape<typeof zhCN>`.
- `src/frontend/src/locales/index.ts` owns selection, persistence, document metadata, `Intl` date/number formatting, and exports structure & interpolation parity validators.
- `src/frontend/src/locales/validator.ts` implements structure parity, interpolation parameter matching, and placeholder checks.
- `useI18nText()` is the Vue integration boundary. UI code consumes typed `messages` or `t()` instead of hardcoding text or importing copy constants.

Missing keys or placeholder leaks never prevent rendering in production. Development and CI fail closed on missing typed keys, structure mismatch, parameter mismatch, or un-translated placeholders.

## Hydration and metadata

Public SSR/AOT output is always rendered in `zh-CN`. Locale storage is intentionally not read during module evaluation or server rendering. `PublicBlogLayoutShell` applies a saved preference in `onMounted`, preserving the first hydration tree and switching labels without reloading article data.

Locale changes update `<html lang>` and `og:locale`. Route titles use the same dictionary where a mapped title exists. Dates and numbers use `Intl.DateTimeFormat` and `Intl.NumberFormat` with the active locale; content bodies, article titles, user names, and other authored content are never machine-translated.

## Governance and validation

Legacy `@/copy` is retired. All translations in `en-US` match `zh-CN` structural keys 1:1 (`satisfies DeepStringShape<typeof zhCN>`). CI enforcement via `check-copy-centralization.mjs` and `validator.test.ts` guarantees fail-closed governance.

## Adding or changing copy

1. Add the `zh-CN` key in the relevant domain file.
2. Add the structurally identical `en-US` value; TypeScript rejects missing or extra branches (`satisfies DeepStringShape<typeof zhCN>`).
3. Consume it through `useI18nText()` and add a focused test for interactive or hydration-sensitive behavior.
4. Run `npm --prefix src/frontend run test:unit:fast -- ../../tests/frontend/unit/locales` and static check scripts.
