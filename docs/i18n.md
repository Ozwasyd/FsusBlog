# Internationalization

FsusBlog supports 10 UI locales: `zh-CN` (Simplified Chinese), `zh-Hant` (Traditional Chinese), `en-US`, `ja-JP`, `ko-KR`, `fr-FR`, `de-DE`, `es-419`, `pt-BR`, and `ru-RU`. `zh-CN` remains the catalog default. Before renderer or cache lookup, Public AOT resolves the request from the canonical `fsusblog.locale` cookie, then `Accept-Language`, then `zh-CN`; the first HTML representation already uses it. SSR, hydration, and direct SPA startup prepare that locale's exact route domains before first render. The independent locale preference contract (`user_locale_preference` + `fsusblog.locale` cookie + `/user/preferences/language`) owns explicit device/account preference; `localStorage` is not authoritative. Legacy `@/copy` constants are retired; user-facing copy lives under `src/frontend/src/locales/`. `src/shared/Contracts/Localization/locale-catalog.json` is the sole editable locale-code/metadata authority; generated frontend and C# projections share its catalog digest. `localeDomainBundleStore.ts` is an independently checked consumer, not a registry. This document belongs to the **Localization and Public UX** capability phase; issue #72's legacy `v1.2.0` wording is not an active product version.

## Runtime contract

- `src/shared/Contracts/Localization/locale-catalog.json` owns locale codes, enabled state, aliases, document/Intl/OpenGraph metadata, names, direction, and script. It cannot contain frontend loaders or UI state.
- `tools/contracts/generate-locale-catalog.mjs` deterministically projects this catalog into frontend and C# generated surfaces; `--check` rejects digest drift.
- `src/frontend/src/locales/keys.ts` derives exact supported identifiers plus mutually exclusive ordinary/plural leaf keys and their interpolation-parameter maps from the `zh-CN` schema. Plural leaves use only `{ kind: 'plural', forms: { other: '...', ... } }`; untagged category objects are not locale messages.
- `src/frontend/src/locales/{zh-CN,zh-Hant,en-US,ja-JP,ko-KR,fr-FR,de-DE,es-419,pt-BR,ru-RU}/` contains matching, independently loadable domain dictionaries (`common`, `public`, `article`, `auth`, `identity`, `layout`, `messages`, `security`, `admin`, `errors`). Every module declares its immutable locale/domain identity. `zh-CN` is the single structure source; all other locales are type-checked against the corresponding `LocaleSchema` domain.
- `src/frontend/src/locales/localeDomainBundleStore.ts` loads an exact `(SupportedLocale, LocaleDomain)` registry entry, cross-checks the module's declared locale/domain identity and schema digest, deduplicates in-flight imports, and caches only successful artifacts. Failure, abort, and a structurally valid wrong-language module never return another language and remain retryable.
- `src/frontend/src/locales/localeFontCatalog.ts` is the generated script/face projection of the same enabled locale inventory. `src/frontend/src/bootstrap/fontPreparationPort.ts` prepares only the target locale's script faces and returns a generation-bound receipt; it never mutates locale runtime state. Idle bootstrap must not preload every CJK face.
- `src/frontend/src/locales/routeLocaleDomains.ts` is the only route/surface required-domain authority. Router consumes it through an injected staged transaction port and does not import the store singleton. Redirects and guard failures roll the candidate back without changing the current domains or messages.
- Public AOT/SSR and hydration prepare only `common + layout + public`; `ArticleDetail` additionally prepares `article`. Their shell does not mount the application-level `SecurityChallengeDialogHost`. Full-app Router routes still prepare `security` for that host, and account/admin shells retain their required auth/security domains. These surface declarations share the same route-domain authority.
- Production build evidence is generated with `cd src/frontend && node ../../tools/frontend/check-locale-domain-bundles.mjs`. It reports raw, gzip, Brotli, and first-request counts for every locale/domain entry and rejects every locale dictionary from the static initial graph. Resolved-locale scenarios prove that only the exact route domains for that locale are requested; there is no fixed `zh-CN` initial bundle.
- `src/frontend/src/locales/runtime/localeRuntimeCoordinator.ts` is the pure active-locale authority. It depends only on injected ports (`domainBundlePort`, `fontPreparationPort`, `preferenceCommitPort`, `metadataPort`, clock, telemetry) and never imports Vue, Router, Pinia, Cookie, localStorage, or concrete font/backend clients. `localeRuntimeComposition.ts` wires browser ports and exposes readonly projection refs. `index.ts` re-exports the composition surface plus `Intl` helpers. Locale switches prepare target domains and fonts in the same generation, optionally commit preference, then publish locale/messages/html lang/dir/OG/Intl in one commit; failure keeps the previous active UI. Route preparation and locale switching share a commit mutex: they stage an immutable snapshot and publish it only after success. Preference UI uses `localePreferenceCommandPort`, which drives the coordinator preference transaction rather than mutating locale first.
- Ordinary and plural resolution are mutually exclusive typed entry points on the readonly locale/domain projection: `translate(key: TranslationKey, params?)` and `translatePlural(key: PluralTranslationKey, count, params?)`. `translate` only accepts ordinary string leaves; `translatePlural` only accepts discriminated plural leaves. Plural category selection uses a `SupportedLocale`-keyed cache of `Intl.PluralRules(descriptor.intlLocale)` (rebuilt when the locale catalog digest changes), reads the selected form from the active domain artifact, auto-injects `count` (caller override is a hard error), and reuses the ordinary safe interpolator. Missing domain, invalid plural node, missing category, missing parameter, count conflict, and non-finite count fail closed with exact error codes; there is no cross-locale fallback, no `other`-as-missing-category fallback, no string-key runtime bypass, and no bundle load / preference / metadata / locale mutation on the resolve path.
- `src/frontend/src/locales/validator.ts` implements the shared ten-locale structure, node-kind, interpolation, placeholder, and plural-form validator used by unit tests. `zh-CN` decides whether a key is ordinary or plural; each target locale must provide exactly the categories reported by its own `Intl.PluralRules`, with `other` and a consistent parameter set containing `count`.
- `tools/frontend/check-locale-domain-static.mjs` is the fail-closed static gate over the exact product of catalog enabled locales × `LOCALE_DOMAINS` (100 artifacts). It checks file/loader/export identity, tree structure, ordinary/plural kinds, interpolation parameters, plural categories, placeholders, source-language dumps, type-only schema imports, route-domain membership, loader keyset parity, bundle-store isolation, and forbids direct dictionary imports from components/bootstrap. Diagnostics always include `locale`, `domain`, `key`, `source file`, `rule`, `expected`, and `actual`. There is no zh/en-only branch, warning mode, allowlist, or `SKIP_I18N_GATE` bypass. The gate runs in local `check:frontend-test-governance` / `frontend-static-governance` and must not be skipped on release-final.
- Static route metadata declares either a dedicated `RouteTitleKey` or `titleMode: 'site-only'`. Action labels, ARIA labels, plural keys, and arbitrary ordinary translation keys cannot be page titles. Display strings are never route identity, and authored article/user/object titles remain raw content outside the translation resolver.
- `useI18nText()` is the Vue integration boundary. UI code consumes typed `messages` or `t()` instead of hardcoding text or importing copy constants.

Missing keys or placeholder leaks never prevent rendering in production. Development and CI fail closed on missing typed keys, structure mismatch, parameter mismatch, or un-translated placeholders.

## Hydration and metadata

`ILocaleResolver` is a pure backend service. It accepts only an already validated explicit cookie locale, the raw `Accept-Language` value, and the catalog default; it does not access a database, authentication store, IP address, timezone, user agent, browser, Vue, or renderer. Header ranges use q/order semantics, ignore q=0 and invalid items, deduplicate ranges, apply catalog exact code/aliases plus BCP 47 parent lookup, and treat `*` as the catalog default. The result carries canonical locale, source, matched range, and catalog digest.

The resolved locale is immutable for one response. It selects the SSR domain bundle and visible copy, hydration `renderLocale`, `<html lang>` / `dir`, `Content-Language`, `og:locale`, `Intl` formatting, Public AOT cache key, and PublicHotRead HTML key. SSR creates a request-scoped locale/domain snapshot instead of mutating process-global state. Contract validation rejects missing or divergent HTML/bootstrap/hydration locale before publication. Hydration prepares that same locale and the exact page domains before app creation and mount; it never reads browser storage to correct the server tree. Direct SPA startup resolves the route and document/server locale, then prepares the exact domains before mounting. Account fixed preference is synchronized onto `fsusblog.locale` at login/refresh so the next Public AOT request sees it without a client hydration switch; anonymous explicit selection and account fixed selection share that same cookie writer.

Public AOT date formatting is bound to the same render snapshot as locale negotiation. The backend supplies one canonical UTC `renderTimestamp` to the renderer, bootstrap, hydration, navigation snapshot, and backfill artifact; missing, blank, invalid, or noncanonical timestamps fail before SSR or seed consumption. Neither server nor browser may substitute a process clock, Unix epoch, `generatedAt` alias, or default locale for this authoritative value.

Public caches use only one of the ten canonical locale codes, never the raw header or account/user identity. HTML responses declare `Vary: Accept-Language, Cookie` (plus encoding where applicable) and `Content-Language`. To degrade all traffic to the default without restarting the application, an operator may temporarily normalize `Accept-Language` to `zh-CN` and strip only `fsusblog.locale` at the trusted edge; existing non-default entries remain bounded and may expire normally. Full code rollback is the previous application image and cache entries from the retired renderer version are rejected.

Locale changes update `<html lang>` and `og:locale` from descriptor fields, never string replacement. Every static route resolves its declared typed `titleKey`; there is no display-string lookup or raw localized fallback. Dates and numbers use `Intl.DateTimeFormat` and `Intl.NumberFormat` with the active descriptor's `intlLocale`; content bodies, article titles, user names, and other authored content are never machine-translated.

## Governance and validation

`LocaleSelector.vue` composes the public FsusUI Dropdown, DropdownMenu,
DropdownItem and Button APIs. Dropdown owns popup positioning, keyboard focus,
Escape/outside dismissal and disabled interaction. The consumer maps `checked`
from the committed active locale and keeps `hide-on-click=false` during resource
work. `retryLocale` carries the failed target separately from the committed and
pending locale; superseded selector requests cannot close the newest request's
menu or replace its failure target. URL items use the public command activation
adapter for navigation and do not submit a locale preference transaction.

The migration requires the checked-item public API from FsusUI #830. Release
qualification still requires an accessible published package with that API,
published/local parity, unclipped bilingual labels and the complete locale/input
matrix. The current source candidate is not a published-mode acceptance receipt.

Legacy `@/copy` is retired. All translations match the ordinary/plural kinds in the `zh-CN` structural tree 1:1 (`satisfies LocaleSchema<typeof zhCN>`). CI enforcement via `check-copy-centralization.mjs`, `validator.test.ts`, `check:locale-catalog`, `check:locale-domain-static`, `check:locale-domain-bundles` (postbuild), and `check:plural-consumer-inventory` guarantees fail-closed governance. The plural consumer inventory is generated from the `zh-CN` schema plus production `translatePlural` call sites; ordinary quantity placeholders, retired prefix/suffix unit keys, and component-level `{n}`/`item(s)` grammar branches fail the gate.

## Adding or changing copy

1. Add the `zh-CN` key in the relevant domain file.
2. Add structurally identical values in all supported locales; TypeScript rejects missing or extra branches and ordinary/plural kind drift (`satisfies LocaleSchema<typeof zhCN>`). For a plural leaf, provide exactly the target locale's `Intl.PluralRules` categories and keep the placeholder set identical in every form.
3. Consume it through `useI18nText()` and add a focused test for interactive or hydration-sensitive behavior.
4. Run `npm --prefix src/frontend run test:unit:fast -- ../../tests/frontend/unit/locales` and static check scripts.
