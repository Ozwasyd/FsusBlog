# Internationalization

FsusBlog currently supports `zh-CN` and `en-US` UI locales. Chinese remains the default and the public AOT shell language, while a visitor's explicit preference is applied after hydration and persisted in `localStorage`. This document belongs to the **Localization and Public UX** capability phase; the legacy `v1.2.0` wording in issue #72 is not an active product version.

## Runtime contract

- `src/frontend/src/locales/keys.ts` owns supported locale identifiers, the default, the storage key, and typed leaf-key inference.
- `src/frontend/src/locales/{zh-CN,en-US}/` contains matching, domain-oriented dictionaries. `zh-CN` is the type source and runtime fallback.
- `src/frontend/src/locales/index.ts` owns selection, persistence, fallback warnings, document metadata, and `Intl` date/number formatting.
- `useI18nText()` is the Vue integration boundary. UI code should consume a typed `t()` key or a reactive dictionary value instead of branching on rendered text.

Missing keys never prevent rendering. Development builds warn and fall back to `zh-CN`; if the fallback key is also absent, the key itself is rendered so the defect remains diagnosable.

## Hydration and metadata

Public SSR/AOT output is always rendered in `zh-CN`. Locale storage is intentionally not read during module evaluation or server rendering. `PublicBlogLayoutShell` applies a saved preference in `onMounted`, preserving the first hydration tree and switching labels without reloading article data.

Locale changes update `<html lang>` and `og:locale`. Route titles use the same dictionary where a mapped title exists. Dates and numbers use `Intl.DateTimeFormat` and `Intl.NumberFormat` with the active locale; content bodies, article titles, user names, and other authored content are never machine-translated.

## Adding or changing copy

1. Add the `zh-CN` key in the relevant domain file.
2. Add the structurally identical `en-US` value; TypeScript rejects missing or extra branches.
3. Consume it through `useI18nText()` and add a focused test for interactive or hydration-sensitive behavior.
4. Run `node tools/frontend/check-i18n-literals.mjs`. It reports remaining hardcoded Chinese copy as warnings during migration. Use `--strict` only for a scoped cleanup where the affected surface is known to be complete.

The warning-only default is deliberate: existing untranslated admin task pages remain usable while shell, public reading, article metadata, auth, and error flows migrate incrementally.
