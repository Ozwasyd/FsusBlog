# Internationalization

FsusBlog currently supports 10 UI locales: `zh-CN`（简体中文）、`zh-Hant`（繁體中文）、`en-US`、`ja-JP`、`ko-KR`、`fr-FR`、`de-DE`、`es-419`、`pt-BR`、`ru-RU`. Chinese (`zh-CN`) remains the default and the public AOT shell language, while a visitor's explicit preference is applied after hydration and persisted in `localStorage`. Legacy `@/copy` constants are retired; all user-facing copy is centralized under `src/frontend/src/locales/`. `src/shared/Contracts/Localization/locale-catalog.json` is the only editable locale-code and metadata authority; its generated frontend and C# projections share a catalog digest. `bundleLoader.ts` is an independently checked consumer, not a registry. This document belongs to the **Localization and Public UX** capability phase; the legacy `v1.2.0` wording in issue #72 is not an active product version.

## Runtime contract

- `src/shared/Contracts/Localization/locale-catalog.json` owns locale codes, enabled state, aliases, document/Intl/OpenGraph metadata, names, direction, and script. It cannot contain frontend loaders or UI state.
- `tools/contracts/generate-locale-catalog.mjs` deterministically projects this catalog into frontend and C# generated surfaces; `--check` rejects digest drift.
- `src/frontend/src/locales/keys.ts` owns the storage key and derives exact supported identifiers plus typed leaf-key inference from the generated catalog and `zh-CN` schema.
- `src/frontend/src/locales/{zh-CN,zh-Hant,en-US,ja-JP,ko-KR,fr-FR,de-DE,es-419,pt-BR,ru-RU}/` contains matching, domain-oriented dictionaries (`common`, `public`, `article`, `auth`, `identity`, `layout`, `messages`, `security`, `admin`, `errors`). `zh-CN` is the single structure source and runtime fallback; all other locales are type-checked against `DeepStringShape<typeof zhCN>`.
- `src/frontend/src/locales/bundleLoader.ts` resolves and loads locale bundles by identifier; its map keys must exactly equal the catalog enabled set.
- `src/frontend/src/locales/index.ts` owns selection, persistence, document metadata, `Intl` date/number formatting, and exports structure & interpolation parity validators.
- `src/frontend/src/locales/validator.ts` implements structure parity, interpolation parameter matching, and placeholder checks.
- `useI18nText()` is the Vue integration boundary. UI code consumes typed `messages` or `t()` instead of hardcoding text or importing copy constants.

Missing keys or placeholder leaks never prevent rendering in production. Development and CI fail closed on missing typed keys, structure mismatch, parameter mismatch, or un-translated placeholders.

## Hydration and metadata

Public SSR/AOT output is always rendered in `zh-CN`. Locale storage is intentionally not read during module evaluation or server rendering. `PublicBlogLayoutShell` applies a saved preference in `onMounted`, preserving the first hydration tree and switching labels without reloading article data.

Locale changes update `<html lang>` and `og:locale` from descriptor fields, never string replacement. Route titles use the same dictionary where a mapped title exists. Dates and numbers use `Intl.DateTimeFormat` and `Intl.NumberFormat` with the active descriptor's `intlLocale`; content bodies, article titles, user names, and other authored content are never machine-translated.

## Governance and validation

Legacy `@/copy` is retired. All translations match `zh-CN` structural keys 1:1 (`satisfies DeepStringShape<typeof zhCN>`). CI enforcement via `check-copy-centralization.mjs`, `validator.test.ts`, and `check:locale-catalog` guarantees fail-closed governance.

## Adding or changing copy

1. Add the `zh-CN` key in the relevant domain file.
2. Add structurally identical values in all supported locales; TypeScript rejects missing or extra branches (`satisfies DeepStringShape<typeof zhCN>`).
3. Consume it through `useI18nText()` and add a focused test for interactive or hydration-sensitive behavior.
4. Run `npm --prefix src/frontend run test:unit:fast -- ../../tests/frontend/unit/locales` and static check scripts.
