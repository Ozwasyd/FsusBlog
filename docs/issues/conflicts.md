# P0 范围和契约裁决

各方案都保留在台账。下列保守边界用于限定当前切片的主张；它们不是上游需求关闭、对外兼容裁决或完整验收。

| ID | 已确认冲突或边界 | 可选处理和影响 | 未决时的实施范围 |
| --- | --- | --- | --- |
| C1 公开响应已裁定 | 固定 v1 HTTP 生产者发送 FSPA cursor v2/100 字节、ARD5 和 FAS4。公开文档明确包含 FAS4 HTTP 搜索。紧凑 FSR4 由本地搜索 Wasm 生成，是另一条契约。 | 保留三种现行 HTTP 响应。#1764 与 #1766 允许本项目的对应客户端收窄到服务器实际产生的格式。#1765 的全局 FSR4-only 将改变公开 HTTP 搜索，须有显式的对外切换决定。 | 对旧 56/76 字节 list、ARD3/4 和无 magic search 的本地历史读取，核实是否对外发行或供持久对象使用。没有此证据时旧 reader 的对外兼容仍未验证。需要本地 FSR4 的功能及向量，当前 HTTP FAS4 不能替代。 |
| C2 首版约束已裁定 | #1860 后续规范评论和 #2322 均冻结八种封闭文章属性类型，#1917 允许插件声明 codec、验证与宿主编辑描述。#1917 同时要求沿用 #1860 已登记的存储、权限和 CAS。 | 在八种已登记类型上提供受控适配、验证和编辑描述。持久类型身份与值保持不变。若 #1917 还要求插件注册第九种存储或跨栈可查询类型，该增量需要独立版本化决策。 | 后续验收需证明插件失败、停用或卸载后，已有数据仍能解析且遵循原权限。暂不承诺任意新字段类型。 |
| C3 运行数据库已裁定 | #1761、#1762、#2218 和 #2221–2223 涉及 PostgreSQL、MySQL、SQLite 的迁移与保全。固定 v1 Server 的初始化只注册 PostgreSQL。MySQL、SQLite 出现在独立离线工具的 DDL 与输入路径。 | v2 服务沿用 PostgreSQL。其余方言延续有依据的离线来源与工具职责。使用实库检查各来源、方言、结构验证和 PostgreSQL 转换语义。#2218 的三个运行时 provider 用例按实际部署边界改为 PostgreSQL 服务拒绝及对应离线输入拒绝。 | 完整生产转换仍需冻结各部署版本，验证权限、历史、凭据、对象和恢复。纯 DDL/查询字串或模拟 provider 不作为通过证据。 |
| C4 | [#3468](https://github.com/Ozwasyd/FsusBlog/issues/3468) 和 [MEM 子项](memory-review.tsv) 要求 Auto memory governor、OS、NUMA、GPU/ReBAR/peer 与 disk spill；当前负载目标和本机测试不覆盖。 | 若采用，单独冻结能力支持、条件激活、预算、供应硬件与多平台证据；若将部分票定为 v1 实现策略，要逐项记录行为替代和压测结论。 | 目前只能证明确实执行的缓存、资源限制和负载；不得用 Unsupported 模拟先进硬件。 |
| C5 已裁定 | #2468 将未知深度解析为 1，#2474 拒绝非法值。固定提交的 `ArticleGraphContract.Validate` 把缺省设为 1，非法深度返回 `invalid-depth`，depth 2 还要求显式展开。 | 按 v1 可观察行为采用 #2474，保留 #2468 的默认深度、scope、预算和权限规则，拒绝未知深度。 | 验收缺省、显式 1、带意图的 2、无意图的 2、0、负数及大于 2。响应显式报告有权限范围内的截断。 |
| C6 事务已裁定 | #2487 的转换计划限于 `explicit-reference-note`，#2490 还允许显式选择 `visual-only`，并提出有序恢复。附件 §5.4 和 #3738 均明确要求真实服务端事务。固定 v1 对象可持久化两种边，未找到已激活的对外转换写入。 | 文章修订、Canvas 变化、幂等记录及 outbox 同事务。按 #2487 安全切片先限制为带语义边。决定是否通过明确用户选择增加 `visual-only` 时，要保留相同确认、端点权限、修订和失败零写入。 | 真实数据库验证失败或取消不产生两步写入，重试不重复链接。视觉边可转换性仍需产品决定。 |
| C7 已裁决 | [#1925](https://github.com/Ozwasyd/FsusBlog/issues/1925)、[#1984](https://github.com/Ozwasyd/FsusBlog/issues/1984)、[#1985](https://github.com/Ozwasyd/FsusBlog/issues/1985)、[#1987](https://github.com/Ozwasyd/FsusBlog/issues/1987) 的自动 npm 发布/消费，与用户要求直接锁定检出的 FsusUI 源码测试合约不符。 | 已按用户范围裁决为旧发布系统限定；继承消费者身份对齐、可重建锁定和真实渲染的教训。 | 不依赖 FsusUI 发行渠道或 v1 自动合并。 |
| C8 已裁决 | [#4759](https://github.com/Ozwasyd/FsusBlog/issues/4759) 中的历史 .NET 11 freshness 建议与 v2 的 .NET 10 LTS servicing 策略不符。 | 使用当前锁定且可复验的 10.0 servicing 工具链；安全修复和漏洞处置仍独立适用。 | 不自动升主版本。 |
| C9 私有附件协议 | #1782 固定 v1 不透明票据和无效、无权、缺失统一 404。#2076 要求统一 403、绑定 PATH/摘要/发行方等信息、跨实例一次消费。 | 沿用 v1 固定入口时使用 404 并保持没有存在性泄漏。若采用 #2076 的单一格式和外部状态语义，需要明确同一协议切换、HEAD 和取消消费规则。跨实例原子消费是服务能力，单改测试或状态码不满足。 | 未冻结前不宣称新版票据/重放防护验收。两种候选都要求统一失败体和 header、拒绝未经授权的存储访问，并检查存在性、时序与代理路径。 |
| C10 属性算子精度 | #2324 的历史契约无区间边界包含、集合等价、文本排序规则、URL host/scheme 操作数的具体定义。 | 在没有对外既有行为时，明确冻结 UTC、区间、集合和协定排序的已定义含义。对未知算子返回不可执行，不能悄悄忽略过滤条件。 | C2 的八种已登记类型仍可继续实现；完整过滤、facet、排序验收需要独立向量、真实查询和权限竞态。 |
| C11 性能数据集 | #2542 / #3654 请求独立 100 万文章规模，既有 nightly profile 是 10 万文章加 100 万评论。 | 分别定义 100 万文章的主查询和 10 万文章加 100 万评论的跨域工作负载，或由验收方明确改变指标。记录分布、硬件、资源时间和场景断言。 | 一种规模的 pass 不能覆盖另一种。若本机无法执行，按对应 profile 记录缺测。 |
| C12 管理列表范围已裁定 | 固定 v1 管理列表把关键字标为文章标题，实际 SQL 匹配标题或摘要。#2320 记录这个差异。全局作者全文检索和 Quick Switcher 分别有独立用途。 | 保留管理列表可观察的标题或摘要匹配，按实际匹配范围标注搜索控件。多个入口可复用查询权威及权限过滤，各自明确字段范围。 | 验证仅摘要包含关键字时仍出现在有权限的管理列表。正文级命中与定位归作者全文检索。 |
