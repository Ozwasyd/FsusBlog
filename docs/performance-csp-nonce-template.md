# CSP nonce UTF-8 segment templates

<a id="决策"></a>
## Decision

Public AOT and PublicHotRead HTML artifacts call `CspNonceUtf8Template` when they are generated or deserialized. The compiler scans the document once, validates the HTML/nonce boundaries, injects compiler-owned slots, and stores a single UTF-8 template buffer with slot offsets. Each request encodes the same 16-byte CSPRNG-generated base64url nonce exactly once, writes it to `HttpResponse.BodyWriter` by offset, and then awaits one `FlushAsync`; it does not create a complete rendered `string` or `byte[]`.

Because the nonce changes the entity of every response, the following caching/compression model is selected:

- `Cache-Control: private,no-store`; do not send an ETag or process the response as 304;
- PublicHotRead L0 uses identity streaming, and `identity;q=0` returns 406;
- do not generate or retain static br/gzip variants for nonce artifacts because they cannot be reused;
- static artifacts without a nonce continue to use release-time br/gzip and variant ETags;
- do not use `CompressionLevel.SmallestSize` inside the request, and do not first assemble and then compress the whole page.

This choice primarily eliminates two full-page copies per request, LOH usage, and compression CPU. Actual page bytes, identity/br/gzip sizes, and before/after CPU/allocation are recorded by `CspNonceHtmlHotPathBenchmarks` and release evidence; if streaming compression is introduced in the future, it must preserve segment-writer, cancellation/backpressure, and no-store semantics, with separate p99.9 evidence added.

Local baseline on 2026-07-14 (Intel Xeon Gold 6230, 8 logical CPUs, .NET 10.0.8, 164,814-byte nonce response):

| Path | BDN mean | allocated/op | profile p99.9 | estimated copied bytes | LOH/op |
| --- | ---: | ---: | ---: | ---: | ---: |
| Legacy full-page decode/replace/encode | 569.206 µs | 781,645 B | 10.618 ms | 967,224 B | 1 array + 2 strings |
| UTF-8 segment writer | 7.044 µs | 0 B | 39.491 µs | 164,814 B | 0 |

Per-request compression evidence for `CompressionLevel.Fastest` in the same profile: identity 164,814 B; gzip 5,673 B, mean 548.329 µs, 11,984 B/op; Brotli 3,683 B, mean 205.387 µs, 15,001 B/op. L0 is before the response-compression middleware, so this decision uses deterministic identity streaming and avoids reintroducing approximately 0.21–0.55 ms of request CPU and allocation; bandwidth-prioritized deployments may implement true segmented streaming compression later, but may not return to a full-page buffer. Complete machine-readable evidence is generated by `--csp-nonce-profile` and BenchmarkDotNet JSON in `.tmp/issue-1060/`; do not commit temporary artifacts.

<a id="csp-hash-可行性"></a>
## CSP Hash Feasibility

For completely static inline `script`/`style` elements without `src`, the compiler automatically generates a SHA-256 CSP source. The manifest shares the lifecycle of the artifact identity and template digest and must not be maintained manually. Nonces are still used: hydration/bootstrap and runtime-inserted content require a uniform nonce, and the hash-only switch has not passed the complete cross-browser security smoke test. Individual clearly static nodes may switch only after manifest generation, artifact-digest consistency, security negative cases, and real-browser enforcement have all passed.

<a id="生命周期与预算"></a>
## Lifecycle and Budget

`PublicAotHtmlArtifact`/`PublicHtmlArtifact` hold the template directly. `PublicHotReadSnapshot` atomically replaces the entire visible HTML map on publication; it does not use `ConditionalWeakTable` or string-object identity. In-flight old requests can safely read the old snapshot; the old template can be reclaimed after the last reference disappears. `ResidentBytes` includes raw/compressed artifacts, the template buffer, slot offsets, and the hash feasibility list; `MaxResidentBytes=0` is derived automatically from the runtime managed-memory limit, an explicit positive value overrides it, and an over-budget publication fails closed while retaining the old snapshot.

<a id="风险与无需重启回退"></a>
## Risks and No-Restart Rollback

- Parser false rejection: retain the current snapshot, invalidate the failed artifact, and regenerate it; never send HTML without a nonce.
- Abnormal L0 behavior: set `PublicHotRead:Enabled=false` through reload-capable configuration so requests return to the normal Public AOT/SPA chain; do not disable PoW, risk gating, or CSP.
- AOT artifact failure: delete the corresponding document cache entry and trigger backfill; the content-hash hydration sidecar may remain.
- Forbidden rollbacks: fixed nonces, cross-request caching of rendered HTML, `unsafe-inline`, or reuse of static compressed bytes/strong ETags.
