# 管理员公开回滚

独立管理员在已配置的 HTTPS 管理域使用 `article.write`。服务默认关闭此入口。开启前停服执行 `admin-article-rollback schema`，并配置 `FSUSBLOG_ADMIN_ARTICLE_ROLLBACK=true`。启动只验证结构，已有文章记录由离线命令维护。

历史来源必须是该文章较早、已记录的公开修订，并同时拥有准确绑定的权利与责任快照。对可独立核实的 v2 历史发布，操作者可以在停服期间使用 `article-responsibility record ARTICLE REVISION` 从标准输入录入经审核的历史证据。JSON 只接受 `responsibleParty`、`basis` 和 `reference`，其中保存负责主体、核验依据及记录引用。同内容重跑返回原快照；不同内容需另行处理。回滚时复制并关联这份证据，普通发布流程不会为已有记录补空责任。

预览显示选择的历史发布、基准修订和当前发布。尚未发布的作者修改、待执行定时发布、私有附件或缺失快照会阻止操作。变更请求绑定当前修订、当前发布、来源修订、理由和命令 UUID，由同一管理员用 Passkey 完成一次用户验证。

一个 PostgreSQL 事务追加新修订、新发布、分类标签、旧版权字段、新责任快照、管理员命令、发布历史和 outbox。文章所有者保持原账号，发布历史的管理员 ID 与作者命令字段独立。同一仍获授权的管理员重试完全相同的命令，返回原始发布回执。普通会话、其他管理员、过期或不匹配的证明、以及已变更的基准均不会产生新发布。事务在既有公开发布门内提交，公开详情、索引和订阅读取新发布坐标。

当前仅支持将当前已公开文章回滚为新的公开发布。草稿及归档目标、历史私有附件进入公开发布、旧签名与透明链的转换另有独立验收要求。

2026-11-15 在 PostgreSQL 18.7、SDK 10.0.404 和 Chrome 157 经 Caddy HTTPS 双域验证。真实管理员 Passkey 完成用户验证；修改命令后证明被拒绝；丢失已提交的响应后，同一命令返回原回执。公开 HTML 与 AEDS 均显示新发布并读取历史权利。原生集成确认待发布作者草稿保留、outbox 写失败时整笔回滚及两个并发重试返回相同发布。临时库与监听器已清理。
