# 管理员文章回滚

有效管理员会话可以在管理域执行文章回滚。配置管理员来源后默认启用此入口，可通过 `FSUSBLOG_ADMIN_ARTICLE_ROLLBACK=false` 关闭。统一的 CLI `plan` 和 `apply` 初始化回滚、归档和回收站恢复所需的表。服务启动时验证结构。

历史来源必须是该文章较早、已记录的公开修订，并同时拥有准确绑定的权利与责任快照。对可独立核实的 v2 历史发布，操作者可以在停服期间使用 `article-responsibility record ARTICLE REVISION` 从标准输入录入经审核的历史证据。JSON 只接受 `responsibleParty`、`basis` 和 `reference`，其中保存负责主体、核验依据及记录引用。同内容重跑返回原快照；不同内容需另行处理。回滚时复制并关联这份证据，普通发布流程不会为已有记录补空责任。

预览显示选择的历史发布、基准修订和当前发布。尚未发布的作者修改、待执行定时发布、私有附件或缺失快照会阻止操作。变更请求绑定当前修订、当前发布、来源修订、理由和命令 UUID，由同一管理员用 Passkey 完成一次用户验证。

一个 PostgreSQL 事务追加新修订、新发布、分类标签、旧版权字段、新责任快照、管理员命令、发布历史和 outbox。文章所有者保持原账号，发布历史的管理员 ID 与作者命令字段独立。同一仍获授权的管理员重试完全相同的命令，返回原始发布回执。普通会话、其他管理员、过期或不匹配的证明、以及已变更的基准均不会产生新发布。事务在既有公开发布门内提交，公开详情、索引和订阅读取新发布坐标。

管理员可将当前已公开文章恢复为作者草稿并撤下原公开版本。草稿请求使用显式目标 0 和独立的 AEDS 32997，通行密钥证明绑定该目标、文章、当前修订与发布、历史来源、理由和命令 UUID。AEDS 32998 返回私有发布坐标及快照编号，重复请求复用同一回执。

数据库同时复制历史内容、分类标签、权利和责任，给新修订分配一个私有发布坐标和下一个发布序号，记录管理员撤回沿革及一条 `retract` outbox。新坐标留存在私有管理员回执和历史快照绑定，当前公开指针在同一事务删除。作者库按草稿展示原作者的新修订。作者后续发布使用下一序号。离线 `verify` 验证来源复制、分配序号、当前指针、私有坐标及撤回事件。

公开、草稿和归档回滚均要求当前文章仍公开且没有更晚草稿或未执行排期。来源限于保有完整快照的较早公开修订。包含私有附件的来源及旧签名转换仍待独立验收。

管理员可选择目标 3 将历史发布恢复到独立归档状态。归档命令分配一个新的私有发布坐标和一个新修订，保留原作者与来源快照，撤除当前公开发布并写入一条 `retract` outbox。管理员使用有效会话按稳定 ID 分页查看当前归档，最多 20 项。作者界面、作者回收站、历史正文、工作区及定时发布不再开放该文章。匿名归档时间轴继续只读取当前公开发布。

再次公开时，管理员从归档列表确认该修订和私有发布坐标，独立通过 Passkey 用户验证并以目标 2 重新发布。恢复复制归档修订及它的权利、责任和分类，并生成新的公开发布坐标、发布序号和可签名事件。归档和重新发布都使用 AEDS 32999/33000，验证证明绑定显式目标和全部坐标。归档列表使用 AEDS 33001。离线 `verify` 核对原始公开来源、归档与再次发布之间的精确衔接、私有发布坐标和 outbox。

归档审核可在同一管理域预览已选修订的原始 Markdown。AEDS 33011 绑定文章、当前归档修订和私有发布 ID，复核当前管理员会话、归档记录、权利与责任快照。预览以只读文本展示，关闭时清除正文。再次发布仍需现有的 Passkey 验证和坐标检查。

固定 v1 的状态 3 来自独立管理员目录，管理员进入编辑器后可提交审核后的编辑再发布。v2 从归档再次发布时复制所选归档修订。跨作者的一般编辑、其他非公开历史来源及附带私有媒体的来源仍在此入口的范围之外。
