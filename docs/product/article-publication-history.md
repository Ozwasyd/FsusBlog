# 文章发布沿革

文章的公开读取继续使用 `article_publication` 中的现行坐标。成功发布为同一文章分配新的公开 ID 和递增的发布序号。发布、替换、撤回和软删除另外在 `article_publication_history` 追加作者操作记录。独立的事件序号按文章递增，撤回和软删除只终止当前公开版本，保留已使用的发布序号。

每条作者操作记录包含文章和修订坐标、操作原因、作者、幂等命令和服务端事件时间。替换、撤回及软删除记录实际终止的公开 ID。草稿保存及历史恢复继续使用独立的草稿事务。现行公开指针、修订、命令、沿革和 outbox 在同一数据库事务提交。相同命令重试重放同一结果。

新库随原有离线 `plan` 和 `apply` 建表。现有 v2 数据库需要先符合当前其他业务表结构。停止服务，通过现有迁移工具对同一目标运行 `publication-history` 和 `verify` 后启动新版。升级事务与服务实例使用同一所有权锁。工具保留每个文章已知的当前发布，以及能够核实的编号和发生时间。对于已经撤回或删除且已用发布序号仍留存的文章，工具记录已知计数与升级时的修订边界，未知的旧发布时间保持空值。更早的已替换公开 ID 在现行表中没有存档。

离线 `verify` 检查已写入的事件链、发布序号、当前指针、命令和 outbox，并报告有发布计数但缺少沿革边界的文章数量。直接载入的测试或数据导入若只携带现行坐标，可通过同一离线命令补齐边界，或由首次授权的公开状态操作在同一事务内建立边界。

直接导入显式发布 ID 时，导入工具应将 `article_publication_publication_id_seq` 的下一值置于所有已使用发布 ID 之后。正常发布继续使用该序列分配 ID。

v1 将立即发布、定时发布、恢复及回滚各自记为新发布。撤回和软删除保留原发布记录，通过文章状态隐藏。v2 的定时发布沿革绑定原计划的幂等命令和作者，实际到期后记录新公开坐标。发布提交冻结权利策略。可见发布回滚、责任历史快照和签名审计仍属后续范围。 [定时发布](article-schedule.md) · [发布权利快照](publication-rights.md) · [v1 固定发布契约](https://github.com/Ozwasyd/FsusBlog/blob/2605b438eed8f16d12ddddf033d08a6fa18fcd12/docs/api/article-publication-revisions.md)
