# 文章发布沿革

文章的公开读取继续使用 `article_publication` 中的现行坐标。成功发布为同一文章分配新的公开 ID 和递增的发布序号。发布、替换、撤回和软删除另外在 `article_publication_history` 追加作者操作记录。独立的事件序号按文章递增，撤回和软删除只终止当前公开版本，保留已使用的发布序号。

每条作者操作记录包含文章和修订坐标、操作原因、作者、幂等命令和服务端事件时间。替换、撤回及软删除记录实际终止的公开 ID。草稿保存及历史恢复继续使用独立的草稿事务。现行公开指针、修订、命令、沿革和 outbox 在同一数据库事务提交。相同命令重试重放同一结果。

所需沿革表结构随 `FsusBlog.V2.Cli` 统一的 `plan` / `apply` 初始化。离线 `verify` 校验已写入的事件链、发布序号、当前指针、幂等命令与 outbox 一致性。

直接导入显式发布 ID 时，须将 `article_publication_publication_id_seq` 的下一值置于所有已使用发布 ID 之后；正常发布继续使用该序列分配 ID。

定时发布沿革绑定原计划的幂等命令与作者，实际到期后记录新公开坐标并在发布提交时冻结权利策略。相关链接：[定时发布](article-schedule.md)、[发布权利快照](publication-rights.md)、[管理员文章回滚](admin-article-rollback.md)。
