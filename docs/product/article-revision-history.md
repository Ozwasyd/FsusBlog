# 私有文章修订历史

作者可以在文章编辑器的 Inspector 打开修订历史。列表按已保存的修订从新到旧排列，标出当前草稿、当前发布和由历史恢复的修订。比较对话框在宽屏并排显示两个已保存修订的标题和原始 Markdown，在窄屏上下排列，标明标题和正文是否变化。窗口缩放时，Inspector 等待比较对话框关闭后切换呈现，Escape 因此能关闭当前比较并交还焦点。基准修订过期或选定版本不可读取时，比较区只显示状态。可以下载选定修订的普通 Markdown 文件。恢复前需要清理编辑器中的未保存更改，并填写 8 至 500 个 Unicode 字符的原因。

- `GET /api/v2/authoring/draft/{id}/revisions.aeds?revision=…` 返回 AEDS 32800。每页最多 20 项，`cursor` 与当前会话、文章和基准修订绑定，同一进程内可继续翻阅。基准变化返回 409，进程重启后从第一页重新打开。
- `GET /api/v2/authoring/draft/{id}/revisions/{sourceRevision}.aeds?revision=…` 返回 AEDS 32801。服务器在同一个授权事务中校验文章所有权、现行基准和历史来源，再读取这两个精确坐标。
- `POST /api/v2/authoring/rollback.aeds` 接受 AEDS 32802。幂等记录锁、现行草稿 CAS、来源副本、新草稿、分类与标签、带执行人及原因的恢复记录和 `draft-rollback` outbox 共享一个提交。重复命令返回原始成功收据。同键不同参数或过期基准返回 409。新草稿发布仍走现有单独的发布命令，现有发布坐标持续生效。

比较对话框也显示早期正文相对当前已保存正文的 UTF-16 长度差。展开 **Saved summary and classification** 时，使用同一比较路径的 `map=metadata` 和当前作者会话读取 AEDS 33068。两个确切修订在同一次数据库查询中读取作者保存的摘要及分类标签关联，名称用当前目录显示，差异按分类和标签 ID 比较。原比较接口继续提供 32801。撤权、过期基准或跨作者请求无法读取元数据。

同一作者会话校验比较的两个已保存坐标后，可选择 **Compare with current editor**。右栏显示同一文章及基准修订的当前标题和 Markdown。摘要及分类编辑器中已载入的本地变更一并用于比较。当前表单仅在浏览器中参与比较，导出仍读取选定的保存修订。有未保存更改时，恢复操作仍须先处理这些更改。

作者可在私有附件面板把当前修订所附图片设为草稿封面，也可清除。封面命令绑定当前会话、文章、修订和幂等键。普通保存继承封面，解除该附件时仅清除新修订的封面。历史比较显示两次修订保存的封面坐标。恢复所选修订时复制该修订的封面及附件。

新库包含草稿封面存储。已有库停止服务并备份后，运行 `article-cover schema`。公开封面、v1 原 URL 迁移、密封源代码差异计划和签名导出仍待实现。独立保存的属性可分别查看各自保存的修订快照。 [定时发布](article-schedule.md) · [发布权利快照](publication-rights.md)

新数据库的 `plan` 和 `apply` 自动安装历史表。在当前其余表结构匹配的旧 v2 数据库上，先停止服务，再用同一 `FSUSBLOG_DB` 执行离线迁移工具的 `revision-history` 和 `verify`，随后启动新版服务。历史列表继续读取已有修订，新增恢复操作开始记录来源和原因。
