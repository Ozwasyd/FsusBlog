# 文章定时发布

作者在文章编辑器的 Inspector 设置、修改或取消发布时间。输入使用 UTC，例如 `2027-01-30T12:00:00Z`。服务器使用 PostgreSQL 时钟确认发布时间严格晚于当前时刻。每次设置、修改和取消都产生新的已保存修订，并保留作者命令收据。继续保存草稿，变更分类，恢复历史草稿，手动发布，撤回和软删除都会清除该修订的待发布计划。

- `GET /api/v2/authoring/draft/{id}/schedule.aeds?revision=…` 返回本作者对应修订的计划和发布状态，使用 AEDS 32825。
- `POST /api/v2/authoring/schedule.aeds` 接受 AEDS 32826，包含文章 ID、期望修订、幂等键和 UTC Unix 毫秒。时间为 0 表示取消。同一键重试会获得原始收据。其他请求改变草稿修订后，旧基准返回 409。

服务使用原有发布所有权与写入闸门，在一次 PostgreSQL 事务中按到期时间和文章 ID 检查最多 16 篇候选文章。工作器在数据库时钟到期时重新核对计划、草稿修订、作者和账号代次。到期前保留旧的公开版本，首次定时发布则始终为私有草稿。实际发布复用计划锚定的修订，同步写入现行发布、沿革与 outbox。撤销账号代次后，工作器会清理到期计划。失败时本批次回滚，后续刷新会重试。

定时检查沿用服务的后台发布刷新周期。公开请求继续读取已有快照。定时发布和替换要求草稿具备已存储的权利策略，并在到期时绑定新发布快照。公开回滚和责任历史快照仍为独立工作项。 [发布权利快照](publication-rights.md)

新数据库在 `plan` 和 `apply` 中自动建表。升级匹配其他业务表结构的 v2 数据库时，先停止服务器并运行离线工具的 `article-schedule`，再运行 `verify`。迁移与服务共用发布所有权和交接锁。
