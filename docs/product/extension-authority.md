# 创作扩展包与操作授权

`Core/Extensions` 实现 P5 创作扩展的本地包验证与进程内授权。包格式取自固定 v1 源码的 `AuthoringExtensionPackages` 与 `ZipAuthoringPackageArchiveReader`。`manifest.json` 使用固定字段和数值枚举，发布者对原始 ZIP 字节提供独立的 ECDSA SHA-256 P1363 签名。宿主先配置精确的归档摘要、来源与信任材料，再通过 `ExtensionPackageVerifier.Verify` 验证。验证要求签名、来源记录、三类内容摘要、宿主平台和公钥有效期一致。归档检查限制条目数量和长度，拒绝路径穿越、链接、大小写冲突和解析歧义。

`ExtensionAuthority` 由可信宿主持有。授权同时绑定包、贡献、能力、用途、会话代次、站点、文档和修订。每个请求 ID 在进程内只可获取一次操作。读取范围、读取选区和写入暂存分别使用封闭的请求类型。撤销同意、替换信任、切换包或更新身份坐标后，旧操作在发布前复核会失败，恢复旧坐标也不会恢复旧同意。命令有并发和时间预算。包替换历史在进程内拒绝降级、同版本异内容和不兼容的状态结构切换。

`ExtensionStaging` 接受宿主配置的 macOS/Linux 私有 `0700` 目录和可信宿主提供的输入流。具备授权的请求使用 `CreateNew` 获取 `0600` 文件句柄，随即移除路径，再向原始句柄写入有限长度。已有同名文件保留原字节。句柄释放完成并复核请求后才返回摘要收据。释放失败时保留首个工作错误及次要故障。暂存目录及其路径由宿主独占控制，此处没有同操作系统身份恶意重命名或进程崩溃后的 inode 回收证明。

测试使用真实签名 ZIP、受控时钟和本地磁盘，覆盖错误签名、来源、密钥撤销边界、时钟回退、非法条目、版本冲突、越权请求、重放、异步暂存期间撤销、并发同请求和磁盘碰撞。运行 `dotnet test tests/Core/FsusBlog.V2.Core.Tests.csproj --filter FullyQualifiedName~ExtensionAuthorityTests`。

生产接入仍需持久化的安装包与不可变信任来源、重启后及最终操作时从原存储复核、服务端真实会话与用户同意接入、文档和导出的正式 IO broker、真实运行宿主与隔离验证。v1 通用 `.fspkg` Hook 运行时、主题和字体属于 P5 的独立能力。本模块没有在服务端注册扩展端点或装载入口。
