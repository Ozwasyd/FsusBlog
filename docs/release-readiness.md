# 发布验收仍需验证的边界

目前的 Git 历史包含可运行的 v2 和多次独立候选。每项证据只适用于对应提交、配置、工具链和输入。最终发布需要从同一冻结提交复验各域并证明完整性。

| 验收项 | 已验证的范围 | 发布前仍需完成 |
| --- | --- | --- |
| 公开发布与读取 | 真实 PostgreSQL + Kestrel + Chrome 的保存、CAS、发布、撤回与 outbox 恢复。已实测旧发布失效、租约交接、冷读限制、标准订阅源与相关文章。 | v1 定时状态和发布历史、不可变 Rights V3 与透明度、热度与索引补丁。 |
| 身份与授权 | Passkey、TOTP、单用恢复码、账号会话撤销、受限评论 PoW 已验证授权和拒绝边界。 | v1 独立管理员、角色及风险/强匿名、持久刷新、恢复与旧凭据切换。 |
| 内容、工作区与沟通 | FsusUI 本地 alias 编辑页与多标签，账号草稿恢复、八类属性、私有媒体、只读工单和私有通知。 | 工作区剩余交互和崩溃恢复、Canvas 图否决路径、资产引用和分片、完整工单管理、订阅和审核。 |
| 迁移与扩展 | 独立 PostgreSQL 初始化和备份恢复，三方言只读及影子转换，签名扩展的离线耐久权限和隔离。 | 真实 v1 数据目标、身份媒体权限对账、备份绑定的可恢复 apply、恢复后激活、运行时插件与导出、主题和字体。 |
| 性能与稳定性 | 原生直连、Caddy TLS、冷缓存、失败恢复、运行时归因均有数据。 | 两次通过固定直连和代理容量门槛、完整长时资源与单机边界证据、独立供给者容量。 |
| 发布包 | macOS 上由锁定引用生成运行包和完整 Git bundle，独立导入后核对摘要、Git 和真实媒体运行。 | 从最终验收提交生成并验证目标平台发布包。外部执行 Docker 验收，单列结果。完整代码量重新计算。 |

未通过的样本保留在 [性能诊断](../tests/Performance/)中。产品和议题边界以[执行状态](status.md)、[风险条款](issues/risk-trace.md)、[发布及身份条款](issues/risk-release-trace.md)和[剩余代码预算](product/code-budget-checkpoint.md)为准。
