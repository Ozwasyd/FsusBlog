## Security boundary and defense in depth

Public runtime accepts AEDS v2 only. Binary endpoints return typed BinaryResults.Frame/BinaryPreencodedFrameResult values through AedsFrameBufferWriter; typed POD writers remain the payload boundary. No legacy text API, JSON fallback, generic stream reassembly, weakened X-Fsus-* headers, PoW verification bypass, or fail-open security behavior may be introduced. Protocol changes must keep the C#, shared contract, POD-size, C++ decoder, TypeScript glue, and tests ABI/wire-compatible.

The deployed layers are:

```text
Network: Nginx/OpenResty TLS termination, HTTPS enforcement, unknown-Host rejection, and trusted client-IP forwarding.
Transport: HTTPS only; production startup rejects HTTP CORS origins.
Application: PoW -> rate limiting -> authentication -> MFA/Passkey -> RBAC.
Data: BCrypt password hashes, short-lived JWTs, isolated sessions, and cryptographically secure randomness.
Client: SameSite, HttpOnly, and Secure cookies; CSP, XFO, XCTO, Referrer-Policy, Permissions-Policy; and human-read proof.
```

## Untrusted assets, privacy, and key separation

A .fsfont package is local supply-chain input. Before writing it, validate the reviewed license, a non-empty local license file, structured package origin/source, the declared SHA-256 of every WOFF2 face, directory boundaries, and the WOFF2 signature. Unknown license/origin, remote URL, hash mismatch, undeclared/out-of-root/non-WOFF2 asset, or executable archive entry fails closed. enable/activate rereads exact bytes from the content-addressed store and rechecks size/hash. The release collector and release-final require fsusblog.font.license.v1 evidence with status ok and no violations. No-restart fallback selects the built-in scope; corrupt persistent metadata is first atomically restored to the last-known-good registry.json. Verification is never skipped and remote download is never used as repair. The full contract is the [font package document](fonts/fsfont-package.md).

Theme CSS is untrusted declarative input. ThemeCssSafetyScanner fails closed unless the exact data-theme scope is stable; it rejects Element Plus internal selectors, remote/unknown resources, script-like URLs, full-viewport fixed overlays, over-budget z-index/filter, unbounded motion, layout transitions, and CSS/asset/preview/selector/depth/!important/duration overages. Activation reopens the archive from content-addressed storage and rechecks the package hash; failure leaves the current activation unchanged. Preview accepts only the server-declared `user-preview:{positiveUserId}` scope; arbitrary request parameters cannot escalate to site-wide, public, admin, or console scope. Shared apply atomically persists activation UUID, package hash, config version, mode, and append-only history/evidence. A browser failure can roll back only when scope, UUID, theme id, and package hash match the current activation; rollback restores the previous complete version and default reset removes the scope pointer. Disable the affected scope or select an installed theme that passes a fresh scan; do not bypass the scanner or relax a hard ceiling. Activation fencing and the complete rollback contract are canonical in [Theme activation runtime](themes/runtime-lifecycle.md). Rollback and default reset do not restart the process and do not alter authentication, PoW, notification stream, or binary transport.

The anonymous-comment runtime contract is fsus.anonymous.comment.v5, public-input layout 6. Public input is limited to is_eligible, may_comment, rate_class=common|unknown, requires_moderation, and root/version/hash binding; exact credential epoch/level, reputation bucket, and account age must not enter tickets, comments, moderation/provider payloads, stats/admin views, or release evidence. The production anonymity-set floor is 20; below it the system merges/reproves or fails closed. The v5 ceremony is not complete and production_usable=false; an old layout, key, or ticket codec is not a fallback. Run check:privacy-zk-prod-release before release and disable AnonymousIdentity:ZkProd:Enabled=false without restart for emergency rollback; existing comments, roots, and vault data remain.

FSUSBLOG_ZK_PRODUCTION_ENABLED defaults to 0. While the trusted-setup manifest has production_usable=false, Docker/Wasm/CI does not read, copy, or publish a proving key or browser prover manifest, while ordinary AEDS/PoW/search/image Wasm still builds. Setting it to 1 requires tools/security/comment-privacy-build-contract.mjs to verify the exact fsus.anonymous.comment.v5/layout 6 circuit, setup, and config; verified ceremony and phase2; complete SHA-256 bindings for contributions, transcript, R1CS, proving/verifying keys, prover bundle, and verifying-key binding; and actual-file, path, retired-layout, and digest checks before expensive compilation. There is no old-key compatibility, recovery, or fallback.

Security-risk persistence uses an independent epoch-scoped HMAC pseudonym separated by IP/device/account domain; request path and User-Agent are no longer retained. Ordinary sessions treat X-Fsus-Device-Fp as untrusted and non-credential. sys_user_session stores only account-scoped epoch-isolated device/network HMACs and browser/OS/form-factor labels: never the raw fingerprint, full IP, or full User-Agent. IPv4 is truncated to /24 and IPv6 to /48. Missing or changed signals cannot independently authorize, bind an account, waive step-up, or broaden revocation. The key-ring, migration, retention, and rollback contracts are [security-risk pseudonyms](security/security-risk-pseudonyms.md) and [session metadata privacy](security/user-session-metadata-privacy.md).

Security-risk event admission awaits a protected local journal under the explicitly configured `FSUSBLOG_DATA_ROOT`; it never opens request-path SQL. The existing SQL normalization owner removes raw Path/User-Agent before journal publication, including direct queue callers. Full, closed, and cancelled scheduling cannot turn a required event into a shed or RAM-only success. Independent per-event AEAD delivery keys use `security-risk-delivery`, not the identity-pseudonym secret. Replay preserves the original identity, time, TTL and pseudonym epoch; only the full normalized PostgreSQL commit postcondition permits ACK/key deletion. Current unresolved failures block the existing security-risk drain participant using opaque references and fixed reasons. This retention changes neither the already-computed HTTP/security decision nor PublicHotRead/Redis score behavior. See the [durable delivery boundary](security/security-risk-pseudonyms.md#durable-delivery-boundary).

Historical VisitLog IP pseudonyms are restricted pseudonyms, not anonymous data. Current read analytics creates neither the pseudonym nor an address/hash in VisitLogMessage. VisitLog:IpPseudonymization remains only for migration-era security-log callers and cannot restore analytics writes. Raw-IP deletion covers backups, WAL archives, logs, Redis legacy keys, and ETL/S3; encryption alone is not deletion, and account-linked lookup must not be rebuilt. Use the [historical raw-IP lifecycle](security/ip-anonymization-lifecycle.md) and [Security-log IP pseudonyms](security/visit-log-ip-pseudonyms.md) for retention, DSR export/delete, audit, and monthly scan details.

Linux production anchors every private-asset path component with `dirfd` plus `openat`/`linkat`/`unlinkat`; directories and final files reject symlinks. Writes first use an unnamed `O_TMPFILE` under `UploadCommitRoot`, validate mode, length, and SHA-256, then atomically link into `PrivateAssetRoot`. Startup compares the two roots' device identity with `statx(AT_EMPTY_PATH)` without creating a probe file. A bounded read-validation cache binds the database hash to the actually opened file descriptor's device, inode, size, modification time, and change time; an identity change forces a full rehash, a change during hashing fails closed, and an unavailable identity is never cached. Before physical deletion, the existing `content_asset_cleanup_queue` records a durable fence that reference writers cannot cancel, so the same cleanup worker can discover and retry failures or interrupted work. Filesystem failures surface only fixed categories and never absolute roots or storage keys.

Private-asset delivery uses only short-lived deterministic binary tickets protected with the shared Data Protection key ring and the fixed purpose `FsusBlog.PrivateAssetTicket.v1`. The default TTL is five minutes; startup rejects values below 30 seconds or above ten minutes. Every redemption rechecks private/active storage state, the bound subject and purpose, and the unique real-time authorization policy; anonymous delivery requires that policy to return an explicit anonymous grant. Missing or duplicate policy, invalid or expired ticket, revoked authorization, deleted asset, and missing bytes all produce the same bodyless `404`. Successful responses use `private,no-store`, `no-cache`, and `nosniff`; Range is rejected. Production writes only `X-Accel-Redirect` and never opens the body, while the external ticket lane disables access logging and the sole physical alias is OpenResty `internal`. Because `content_asset` has no sanitized display-filename authority, the response omits `Content-Disposition` instead of deriving one from AssetId or storage key.

Jwt:SecretKey is only for JWT signing/validation and is never derivation material for another security domain. New JWTs put Jwt:KeyVersion in JOSE kid; validation accepts only the current key or an exact-version Jwt:PreviousKeys entry before AcceptUntilUtc. Unknown/expired versions fail closed. Tokens without kid are accepted only during the explicit one-time Jwt:LegacyNoKidAcceptUntilUtc migration window, never by try-all. Production requires unique versions, at least 32 bytes per independent key, and a window not longer than Jwt:RotationWindowDays. The two-phase blue/green procedure and no-restart traffic rollback are in [JWT signing-key rotation](security/jwt-key-rotation.md).

Admin authenticated request lifetimes are server-only registrations owned by the original `AdminSessionProjection`. Actual admin validation registers under the same projection gate after checking `admin_id`, `admin_sid`, token hash, principal status, revocation, versions, generation, readiness, and idle/absolute expiry. The existing JWT success path alone attaches `IAdminAuthenticatedRequestFeature`; a caller SessionId or a mocked `AdminSessionValidationResult.Valid` cannot create the feature. `EndpointUserContext.SessionId` keeps its ordinary `sid` meaning. Each request has a nonsecret, randomly salted binding digest, a cancellation token, and currentness checks. Registrations are capped at 4096 per projection, expire within two minutes or the earlier session/JWT deadline, and are released on abort/response disposal. Matching original projection updates, pruning, expiry, and readiness withdrawal invalidate registrations under that gate; cancellation callbacks execute outside it. Existing local and distributed appliers remain the only delivery path. Local notification begins when the update reaches this node, not at the remote authority commit.

Final private read publication uses `AdminAuthenticatedRequestLifetime.PublishReadAsync`, which owns a PostgreSQL ReadCommitted transaction and retains principal-then-session `FOR SHARE` locks through the bounded read and actual publication callback. `VerifyAndFenceAsync` instead uses the caller's exact original open connection/transaction and leaves those locks held until that caller commits or rolls back. Both check real `admin_principal`/`admin_session` identity, token hash, validation versions, status, revocation, exact expiry facts, and fresh database time after lock acquisition. Generation is a local delivery coordinate; no independent SQL generation column exists. Neither a last reread nor another connection provides exclusion. These APIs reject other providers and isolation levels. Callers must link cancellation, keep publication bounded and complete it before returning, and retain their original transaction through the relevant commit. Row locks serialize SQL authority changes; they cannot make network publication, wall-clock passage, local readiness withdrawal, or a later commit failure reversible. This producer does not establish Canvas/browser/native acceptance.

Integrity proof signing is a separate domain. SiteIntegritySigningService uses the built-in .NET ECDSA_P256_SHA256 algorithm and the fsusblog.integrity.publish-proof.v1 domain separator; it does not use Ed25519 without a separately reviewed dependency. Private keys come only from server-side environment variables, secret volumes, or controlled configuration, never logs, browser responses, public manifests, or C++/Wasm. Missing production signing configuration yields Disabled/Pending and never a fake signature. A revoked key verifies historical signatures only before revokedAtUtc; a compromised key verifies nothing. See [Site Integrity Signing Keys](integrity/site-signing-keys.md).

PoW signing, sealed perception, Recovery Key lookup/hash, anonymous issuance subject rate-limits, security-log IP pseudonyms, region-policy IP hashes, and HumanReadProof:Dedup each use their own key. Leakage affects only that domain. ASP.NET Core Data Protection uses an independent X.509 RSA certificate to protect shared key-ring XML. Production requires DataProtection:KeyProtection:Mode=Certificate, a current PKCS#12 path, and ApplicationName=FsusBlog; missing/invalid/expired/no-private-key protection or legacy plaintext keys fail startup. The certificate private key never enters the shared ring, image, or backup. Blue/green slots share the ring and use current plus previous certificates during rotation; Cookie, antiforgery, and Data Protection wire semantics do not change. See [Data Protection Key Ring At-Rest Protection](security/data-protection-key-ring.md).

Logs, audit, metrics, and structured fallback never print raw client IP. PoW/crawler logs may use only VisitLogIpPseudonymizer's security-log 128-bit UTC-day pseudonym; analytics does not use analytics IP pseudonyms. No path falls back to raw GetClientIp(), RemoteIpAddress, X-Forwarded-For, X-Real-IP, or another key. Ordinary logs also exclude raw PoW salt, MFA AccountId, audit TargetId, SQL text/parameters, LocalAuth fixture stdout/stderr, local absolute paths, moderation dictionary exception messages, issuer key readiness, raw User-Agent, raw request path, and reversible token/proof/challenge material. Readiness/startup output uses fixed categories, not exception text or runtime types; troubleshooting uses only short hashes, fixed categories, counts, or low-cardinality state.

Filesystem paths and local script execution first use Path.GetFullPath and then Path.GetRelativePath to prove the expected root; string StartsWith is insufficient. LocalAuth may execute only tests/frontend/fixtures/prepare-auth-smoke-users.mjs. Public AOT hydration sidecars stay under the web root, SSR worker scripts under the frontend client root, and upload/image/integrity assets under PublicAssetRoot or the instance-scoped UploadSessionRoot/UploadCommitRoot sandbox. Absolute paths, .. escape, out-of-root paths, control-character log input, and similar violations are rejected or degraded without echoing path details. Unix `Platform=Unix` canonical-boundary evidence uses `CanonicalPathBoundary`: it creates a real outside-root directory link and an inside-root link; Windows records the test ID as `not-selected` and does not claim junction/reparse-point coverage.

Before expensive DB, regex, tokenizer, or ArrayPool work, anonymous/background text has explicit bounds: search keyword 128 characters; search-index body 256 KiB; CJK continuous segment 4096 runes; ContentFilter 256 KiB before renting `ArrayPool<char>`; authoring binary body 1 MiB with independent draft MaxLength; comments 1000 characters/4096 UTF-8 bytes by default and at most 3000/12288 through the hot anonymous-comment policy; comment frames 16 KiB; subscription email 254 characters; navigation snapshot path 512 characters; LocalAuth redirect 2048 characters and storage-state JSON 256 KiB; audit page number 50000. Over-limit input returns validation/empty/fail-closed before the expensive path and is not delegated only to Kestrel or database Take. Passkey assertion JSON is separately limited to 64 KiB and 32 nesting levels; the parser rejects before JsonSerializerOptions initialization or deserialization and never enters the Passkey domain service.

AEDS pooled response buffers are sensitivity-first. Unknown, auth, session, MFA, Passkey, anonymous-credential, admin/private, and error frames always use clearArray:true. Only a frame individually registered in AedsFrameSensitivity as a public immutable response may skip final clearing after Seal(frameType). An intermediate buffer replaced during writer growth is always cleared because its frame type is not yet known. New frames default to clearing; global clearArray:false is forbidden. If public classification or cache ownership is suspect, existing cache action/version invalidation clears the raw frame and PublicHotRead snapshot so requests rebuild through L2/dynamic paths; sensitive and unknown frames are unaffected and no restart or clearing relaxation is allowed.

A generated public immutable artifact is not permanently public. Delete, permanent-delete, recycle-bin purge, or Draft/Scheduled/Archived transitions first persist a generation tombstone before the asynchronous projector. Each edge loads unconfirmed markers through Redis Pub/Sub and fails closed; only a persisted CDN purge receipt permits local rebuild. A marker hit returns a bodyless 410 Gone with no-store, X-Fsus-Generation, and X-Fsus-Revoked, and removes validator/encoding headers. CDN purge uses a generation idempotency key; a provider outage retries the mutation/outbox while the origin and notified edges remain fail closed. Tombstones, response headers, and Pub/Sub payloads contain no bearer token, delete reason, title, account, IP, or request path. Only a replacement-snapshot worker may generation-compare-delete a marker; stale workers, duplicate outbox, and out-of-order clears cannot clear a newer revocation. PublicHotRead:Enabled=false is a no-restart fast-path switch only; the revocation middleware remains active. Production verification needs local 410 smoke, provider request/receipt, and another edge's revoke/clear receipt; without a provider receipt, claim origin fail closed only.

## HTTPS response compression isolation

ResponseCompressionMiddleware compresses no endpoint by default. Brotli/Gzip is allowed only for a public GET/HEAD endpoint carrying both AllowAnonymous and PublicResponseCompressionMetadata, with final status 200, explicit Cache-Control: public, safe Vary, and no Set-Cookie, Content-Disposition, or existing Content-Encoding. The allowlist is feed, sitemap, robots, and the public integrity manifest; media types are fixed to application/atom+xml, application/feed+json, application/json, application/rss+xml, application/xml, and text/plain.

Any Cookie, Authorization, X-Fsus-Csrf-Token or common CSRF header, authenticated principal, authorization/antiforgery metadata, WebSocket, notification stream, /auth, /admin, /account, /user, /manage, /internal, /api/binary, non-200, private/no-store/no-cache, Cookie/Authorization/CSRF-varying response, or HTML/binary media type is identity. Random-CSP-nonce SPA fallback is identity. Public HTML/AEDS may use pre-generated br/gzip only when generated at publication as an immutable artifact with no request reflection. The nonce HTML compiler rejects malformed self-closing markers, illegal unquoted attributes, and attribute-bearing script/style closing tags; a cancelled request never writes template bytes to the response pipe before flush reports failure. Errors never reopen dynamic compression.

If allowlist or proxy-cache behavior is suspect, hot-set ResponseCompressionPolicy:Enabled=false; the next request disables general endpoint compression without restart while auth/admin/account/notification/binary remain identity. Re-enable only after negative header/cache/BREACH smoke. This switch does not change PublicHotRead immutable-variant negotiation.

## Proof of Work, rate limiting, and RiskControl

Generated security catalogs below own challenge kinds, verification/cache windows, numeric bounds, rate policies, and fail modes. This section provides relationships and runtime behavior, not a second policy table.

PerceptionCharacterV3 allocation is controlled only by IPerceptionCharacterV3ResourcePlanner. It requires 0 <= critical < low < high for representation/total, positive minute and rolling-hour leases, exact-byte egress budgets, positive IP-prefix/server-device/subject/action quotas, and a complete exhaustion disposition for comment/enrollment/account-recovery/admin-sensitive/public-read/other. Startup validates the pool before traffic; missing configuration, unordered watermarks, an hour budget below the minute budget, or a missing disposition fails closed. The v1 pool manifest's additive non-secret artifactBytes is ignored by old runtimes but authenticated at startup against decrypted final PNG/Ogg bytes and the hard limit. One Redis Lua transaction covers entry burn, ready/leased inventory, byte budget, identity quotas, and the retry fence; ambiguous replies cannot rent or charge a second item. Redis keys contain only isolated IP-prefix/server-device/subject/action/operation hashes and no raw IP, answer, token, media, challenge ID, or free-text reason. Hot-set Security:PerceptionCharacterV3:Resources:AllocationsEnabled=false to queue or fail closed by action; restore only after generation, inventory, and budget health checks, never a retired generation. This does not change public reads, notification stream, or binary frames; existing challenges only verify/cancel through expiry drain and never return to online rendering. Startup Security:PerceptionCharacterV3:Enabled=disabled does not register the provider; legacy-derived default policy converges to registered sha256PowV1, while an explicit perceptionCharacterV3 policy import is rejected rather than silently rewritten. Enabling V3 requires provider, pool/startup gate, and policy together.

## Anti-crawler loop

ShieldMiddleware classifies requests before ordinary endpoints. Exact search crawler and social-preview families precede generic bot|spider|crawler matching. Googlebot, Google-InspectionTool, bingbot, and msnbot require CIDR validation; Baiduspider and Sogou require rDNS plus forward DNS. Only validated crawlers set `HttpContext.Items["VerifiedCrawler"] = true`. In observe mode, a failed verification is allowed through with a FakeCrawler risk event but never gets the verified flag or high-quota partition. Twitterbot, facebookexternalhit, Discordbot, Slackbot, TelegramBot, LinkedInBot, and WhatsApp may GET/HEAD only public HTML, OG/static resources, and robots.txt, never /api/**. Unknown bots, tool UAs, and empty UAs receive a light 403 and a fsus.security.event.count signal; traversal, double slash, backslash, and double-encoded paths call Abort() and record a metric.

CrawlerUpdateWorker's source order is official HTTPS JSON (Google googlebot.json or Bing bingbot.json), local last-known-good snapshot, Security:CrawlerCidrs:* configuration, then empty degraded. URLs are HTTPS on developers.google.com or <www.bing.com> with the default HTTPS port only; startup, admin updates, and worker requests enforce this and reject invalid URLs without falling back to an old URL. Snapshot paths are relative, canonicalized under FSUSBLOG_DATA_ROOT/security, and reject absolute, .., drive-letter, or colon paths. The default interval is 1440 minutes and the minimum is 30; reloadable CidrAutoUpdateEnabled, CidrUpdateIntervalMinutes, CidrMinUpdateIntervalMinutes, provider URLs, and snapshot path are observable through admin-only GET /api/ops/crawler-ranges/status and /api/binary/admin/security/anti-crawler/crawler-ranges/status, with manual POST /api/binary/admin/security/anti-crawler/crawler-ranges/sync.

ISecurityRiskSignalSink, ISecurityRiskScoreReader, and ISecurityRiskPolicyProvider carry a stable source for Shield, RateLimiter, PoW, HumanReadProof, pospace, device-fingerprint, region-policy, comment-governance, admin-step-up, and risk-control. PublicHotRead is the exception: its gate reads only the bounded local `PublicHotReadRiskProjection` and never synchronously invokes `ISecurityRiskScoreReader`; the strong Redis score path remains for non-public operations. Unknown reason numbers retain their original numeric string. Redis serves the strong risk hot path and PostgreSQL the durable event path; persistence failure does not alter the current decision, and raw IP/device data is not stored. RiskDecisionService maps context, active policy, and score to allow/challenge/block; public reads move artifact bytes only after their gate.

Passkey login and ordinary-account step-up read the credential, `passkey_credential.xmin::text` rowVersion, and `sys_user` status/deletion/passkey user handle in one PostgreSQL query. The verified assertion updates only with `signcount = @expectedSignCount AND xmin::text = @rowVersion`; a CAS conflict rereads counter/rowVersion, allows the assertion if the database already reached its value, retries one CAS if it is behind, and otherwise fails closed without calling it a clone. Counter state is explicit: `0 -> 0` is `Unsupported` and does not revoke a session; `actual > stored` is `Advanced`; a non-zero `actual <= stored` is `Risk`, always rejected and audited. `PasskeyCounterRisk:ResponseAction=reject_credential` is the safe default; only an explicit hot setting of `revoke_account_sessions` revokes active `sys_user_session`, bumps `AccountSnapshotVersion`, and emits an identity-free `SessionRevoked`; missing/unknown settings never broaden this response.

Cross-tab authentication uses transport-only `authBroadcastRuntime` for BroadcastChannel/localStorage fallback and projects only `{ type, at }`; it imports no Pinia/Store and drops token, session, account/admin, and proof fields before subscribers. `authBroadcastComposition` injects the account logout publisher and notification session-revoked callback, separates account/admin events, deduplicates equal type/timestamp events, and rebinds after dispose/rebuild. The transport may be hot-disabled, but server session checks, notification `SessionRevoked`, and the next request remain authoritative.

Account `guest` and admin `missing` are short-lived current-tab/current-page-epoch negative caches only. LocalStorage never stores an auth conclusion or `/auth/me`/admin-session bypass marker; initialization removes legacy `fsus_user_storage`. Login, switch, Passkey completion, admin step-up, matching login/admin-changed broadcasts, and focus/visibility reset both values to `unknown`; logout/expiry may establish only the current event's confirmed `guest`, while network uncertainty remains `unknown`. `authenticated` and admin `active` require the server HttpOnly Cookie/session snapshot plus the current principal, and neither negative state grants permission.

Passkey complete, MFA verify, and anonymous bootstrap share one post-auth commit after Cookie write: invalidate the current guest cache, force `GET /api/binary/auth/me`, and mark the session active, broadcast login, or enter private routes only after `userStore.isLoggedIn=true`. `ensureBootstrap`, a response user fragment, or Cookie success cannot substitute for this read. A global generation keeps only the newest commit and aborts its owned request on unmount; failure, cancellation, or uncertain networking stays public and does not broadcast success.

Before issuing a challenge, capability preflight independently verifies that the kind is parseable, the provider is registered, the client executor exists, and the UI/headless host is reachable. UI and notification-headless share one registry; a placeholder slot or present component is not capability. Unknown manifest versions, missing provider/executor/host fail closed without logging high-entropy device, account/admin, token, or proof data. Disable the affected RiskControl/Perception subsystem or restore last-known-good policy without restart; never re-enable a placeholder kind as fallback.

RiskControl providers implement ISecurityChallengeProvider. Filters do not depend directly on PoW, Perception, PoSpace, HumanReadProof, or Passkey implementations. SecurityChallengeOrchestrator resolves the ordered RiskDecision.RequiredChallenges from DI, lets each provider persist before returning its assignment, and assembles the envelope only after every provider succeeds. Missing providers, provider failures, invalid assignments, and proof mint failures fail closed, record SecurityChallengeRejected, and do not enter the handler. A successful verify yields one opaque proof with an authoritative absolute expiry; the later filter decides access. Public failures are limited to expired, replayed/missing, binding mismatch, revoked, and generic rejected; Redis identities and detailed subject/IP/device checks remain private. A business rejection after proof consumption cannot trigger client recovery.

Every combination gets a UUIDv7 envelopeId with at most eight ordered members; a single challenge is memberCount=1. Redis keeps TTL no later than the shortest member expiry and uses versioned CAS for envelopeId, next ordinal, member state, action/route/subject/client/device binding, and policyVersion. The process cannot replace that CAS with read-modify-write, client-reported completion, or PostgreSQL audit replay. PostgreSQL security_challenge and security_challenge_attempt are the per-member audit truth, with states issued|verified|expired|replayed|failed|revoked; Redis envelope states are active|completed|failed|expired|revoked. Payload/proof/raw IP/device are never persisted. `FsusObservability` records `fsus.security.challenge.issued.count`, `fsus.security.challenge.verified.count`, `fsus.security.challenge.failed.count`, `fsus.security.challenge.replayed.count`, and `fsus.security.challenge.solve.duration` with low-cardinality tags. `ConsumeProofAsync` uses Redis GETDEL/consume-once to consume aggregate proof before comparing all bindings; replay, miss, mismatch, wrong kinds, incomplete/replaced envelope, or expiry is rejected and recorded, and the handler is not entered. The endpoint verify limiter is the sole ISecurityChallengeVerifyRateLimiter: SecurityChallengeVerifyRateLimit uses atomic INCRBY+PEXPIRE, a one-minute window, two-minute TTL, and three attempts, with identity verify:{windowStartTicks}:{clientIpHash}:{deviceFpHash}:{normalizedAction}:{challengeIdHash}; the key has no raw identifiers or minute-rounded identity.

Challenge V2 audit delivery uses independent normal/high-value protected journals under the explicitly configured `FSUSBLOG_DATA_ROOT`, with per-event AEAD keys in the separate `challenge-v2-delivery` domain. Each newly created event allocates one GUID when its identity is missing and captures its normalized attempt/created timestamps; reusing an unprepared request does not merge independent events. Full, closed, and cancelled RAM scheduling retains required pending events without request-path SQL. Authenticated journal bytes own recovery metadata; the private request binding only transports `CreatedAtUtc` through the unchanged persistence interface. Replay remains high-first and FIFO within each lane, checks every normalized PostgreSQL attempt field for duplicate/commit proof, and does not repeat the business state transaction for an exact duplicate. A retained encrypted committed witness preserves the private clock for explicit identity retries; it and its key are not silently discarded or treated as a content deduplication rule. Each lane independently caps live leases and its RAM current-failure reference index at 64 entries; sources beyond the lease limit remain in the protected journal. Current failures are attributed only to opaque references, and only the matching admission recovery or proven commit clears them; unrelated successful events cannot clear another failure. Failure-index exhaustion retains an opaque unknown fail-closed blocker, not an exact all-queue failure count, even after known events recover. Historical failure occurrences remain separate from current blockers. Cancellation returns its lease once, and proven corresponding recovery clears the tracked blocker. This is same-data-root/key process crash/restart recovery, not a power-loss or cross-node guarantee; Redis authorization/envelope state, HTTP decisions, payload contracts and challenge priority classification remain unchanged.

RiskControl actor context keeps ordinary accounts and `AdminPrincipal` separate: `identity_kind=anonymous_account` may carry `UserId/AccountSubjectHash/SessionId`, while `identity_kind=admin_principal` carries only `AdminPrincipalId/AdminSessionId`; ordinary `UserId/SessionId` are null for the latter. Authenticated subject hashes derive only from `identity_kind + account_subject_hash`, never `ClaimTypes.NameIdentifier`/`nameid`; a legacy session without `account_subject_hash` falls back to `clientIpHash` for risk-event persistence. Aggregate proof uses `X-Fsus-Challenge-Proof`, never admin-sensitive `X-Fsus-Mfa-Proof` or legacy `X-Fsus-Pow-Proof`; only an envelope CAS confirming all ordered members may call `ISecurityChallengeProofService.MintProofAsync`. Claims bind envelopeId, ordered kinds, final member challengeId/kind, action, route, subject/client/device hashes, issue/expiry, nonce, and policyVersion, while the compatibility headers still use the final member values. Multiple tokens, first-member-only completion, or client-reordered kinds are rejected.

`FsusObservability` records `fsus.security.risk.event.count`, `fsus.security.decision.count`, and active policy gauge `fsus.security.policy.version.active` plus provider-missing/exception/proof-mint failures. Listener/exporter errors are swallowed at the observability boundary and never change the decision or business code. Protected `/api/ops/health/ready-detail` reports `riskControl` only when active and last-known-good policies, Redis consume-once, and the provider registry are usable; missing policy or one-use storage returns `not_ready`, while public reads follow only an explicitly allowed degraded policy.

Browser proof is typed and process-memory-only: never LocalStorage, SessionStorage, URL, BroadcastChannel, logs, telemetry, or error context. Reservations isolate concurrent requests; only a definitely-not-started fetch may recover, while a request that might have reached the server must reissue. Login/logout/account-switch/admin-session changes clear the store. The notification preflight consumes the proof and creates a path-bound, HttpOnly, SameSite=Strict grant; reconnect never reuses it. Hot rollback disables the multi-challenge band, an affected action, or globalMode=observe, or restores the last-known-good policy; issued multi-member envelopes fail closed and never downgrade.

## PerceptionCharacterV3 protocol and runtime

The breaking protocol identity is wire name perceptionCharacterV3 and algorithm fsu.challenge/perception-character-artifact@v3; the sole byte-level authority is [PerceptionCharacterV3 final-media protocol](security/perception-character-v3-protocol.md) and its contract at src/shared/Contracts/Validation/Security/perception-character-v3-contract.json. The retired raster/gray8/audio-wav identity, old dimensions/layouts, V1/V2 aliases, V4, dual decoder, migration adapter, and compatibility parser are rejected and cannot be restored by rollback. The public issue payload contains only challenge/envelope identity, representation, final media type/bytes, dimensions, attempt budget, policy version, timestamps, and opaque state token; never answer/tag, glyph/atlas, seed, recipe, transform/noise, phoneme order, key material, or an answer oracle.

Runtime reads identity/alphabet/artifact bounds/crypto sizes only from the embedded contract, never the reference script. Answer, token, and pool encryption use three independent versioned 256-bit rings. Startup rejects missing/non-32-byte/equal/unknown/invalid/placeholder/checked-in-vector keys, invalid active generation, and unauthenticated pack; test vectors require `environment=Test && AllowTestVectors=true`. Server-issued device authority is domain-separated HMAC and is bound with pseudonymous IP, subject, action, route, envelope/challenge, issued policy, representation, and media hash into AES-GCM state and authoritative Redis state. Authenticated/admin authority is from server session claims; anonymous authority is a Redis lease plus __Host- cookie; client fingerprint cannot create or rotate a device bucket. Redis Lua validates all binding, expiry/revoke, and two-attempt accounting atomically. Timeout, connection failure, or ambiguous result fails closed and logs only low-cardinality operation/outcome/reason.

Initial issue uses one Redis state+TTL+active-index NX script. The index is a server-device stable digest independent of answer/token rotation, never a challenge-specific DeviceBindingHash. Refresh or representation switch CASes the old binding/index, revokes the old state, creates a fresh TTL state, and exchanges the index in one script; old binding uses the old recorded answer-key version and a new challenge uses current. A lost script reply is resolved only from the same operation result; uncertainty leaves an ambiguous fence and rejects later mutation. Hot removal of perceptionCharacterV3 stops issue and replacement, then cancel/revocation may retire active identities. Existing challenges use their envelope policy version; ordinary policy publication does not kill them, while explicit revoke always wins. Dynamic-import startup recovery uses fixed SessionStorage key `fsus:bootstrap-import-retry` containing only low-sensitivity build id/time; Public AOT and Full SPA share one reload controller, cleared on successful startup, build change, or five-minute expiry, while storage failure leaves the original error. Enabled and key-ring changes are startup boundaries and recovery uses an independent prior valid ring, never JWT, PoW, or V2 keys.

The browser validates algorithm, UUIDv7 identity, representation, time window, attempt budget, slice bounds, and final PNG/Ogg Opus structure/size before creating restricted image/png or audio/ogg; codecs=opus Blob URLs. Replacement, close, route changes, and unmount release URLs/audio/bitmaps. Verify returns only typed algorithm/challengeId/envelopeId/representation/answer/stateToken; it does not produce or log duration, recipe, seed, glyph id, risk score, answer verifier, or internal reason. Pending commands show unavailable or can cancel; other challenge kinds and notification stream continue. Recovery requires the backend provider and current local FsusUI primitive, with no V1/V2 alias.

`perception-sealed@v2` is retained only for `perceptionLocalizationV2` and `perceptionMicroInteractionV2`. `IPerceptionSealedTokenService` emits an AES-GCM token whose payload contains only the challenge/task/action/route, subject/client/device/UA hashes, algorithm/family/variant, recipe hash, expected point or step hash, tolerance, duration, attempt, nonce, keyVersion, and policyVersion; the envelope exposes only non-secret AAD. `Security:PerceptionSealedToken:CurrentKeyVersion` and `Security:PerceptionSealedToken:Keys:{version}` rotate keys; unknown versions, tampering, binding/context mismatch, and expiry fail closed. This sealed token has no Redis consume-once semantics and cannot replace ordinary challenge or admin MFA proof. V3, LocalizationV2, and MicroInteractionV2 share `SecurityChallengeEnvelope`, assignment, one-use proof, and action/route/subject/IP/device/policy binding, with no cross-version or parser/schema fallback.

Client renderer, Worker, DOM events, pointer coordinates, steps, solve duration, and provider payload are attacker-controlled. Public issue data excludes expected answers/coordinates/steps, semantic labels, raw identity/network data, UA, proof, admin session, and answer oracles; the server trusts only assignment binding, sealed token, RecipeHash, Redis attempt/consume-once state, and the policy snapshot. Issue selects only V3, LocalizationV2, or MicroInteractionV2; verify checks their binding and (for V2) decrypts AEAD before coordinate/step validation; proof mint remains one short-lived `X-Fsus-Challenge-Proof`. Localization normally combines with sha256PowV1, MicroInteraction is strict-policy opt-in, and capability-limited PoSpace can only cause a server-authoritative reissue or rejection. Rollout is `observe -> V3/localization enforce -> micro-interaction optional -> strict/lockdown`; rollback moves the action to `observe` or restores last-known-good and never revives retired kinds, schemas, JSON fallback, or weak proof binding.

The production build gate is disabled by default and must preserve the anonymous-comment v5 gate above. The independent release gate generates the deterministic visual/audio corpus, checks uniqueness, unbiased answer position, baseline recognizer, PNG/Ogg structure, byte budgets, Redis repeated cutover idempotency, retired-renderer cost, and zero leases for 1,000 pre-admission rejections. Implementation and independent-review receipts bind the same full commit, release target, pool generation/manifest, corpus/benchmark/migration hashes, and immutable commands; any high/critical finding, digest drift, or sensitive evidence fails closed. Production shared RiskControl currently covers `auth.passkey.begin`, `auth.passkey.complete`, `recovery-key.verify`, and comment/reply only; legacy `auth.login` is migration/test-only. `PasskeyAssertionFailed` and `PasskeyAssertionAccepted` remain the positive/negative signals, and `mfaVerified=true` completes Passkey login. Account self-service and admin commands do not have a shared RiskControl proof endpoint; admin-sensitive operations keep X-Fsus-Mfa-Proof. Future inclusion requires the server endpoint and shared coordinator and reuses the sole SecurityChallengeDialogHost.

## Human-read proof

Public GET has no view-count side effect. HumanReadProofService is the only source of article Views and admin statistics. Challenge: POST /api/binary/read-proof/challenge.aeds with HumanReadChallengeRequest; submit: POST /api/binary/read-proof/submit.aeds with HumanReadSubmitRequest. After SPA hydration, main content must be visible for at least eight cumulative seconds; read-proof sends no stable device fingerprint. The challenge binds scope, routeKey, articleId, a 15-minute epoch, article/epoch-scoped HMAC digest, issue/expiry, minimum dwell, and nonce; the digest is derived from transient IP/UA and not retained after the Redis lease or token. Reject no-JS/unhydrated AOT, direct API, missing Fetch Metadata, cross-site Origin/Referer, crawler/verified-crawler UA, insufficient dwell, expiry, tampering, and replay.

Acceptance writes the human-read-proof negative risk signal only to reduce public.read risk; rejection/limit writes ReadProofRejected but never blocks content and never authorizes comment/auth/admin writes. Before enqueue, accepted events are reduced to UTC hour, article/site type, and one of four dwell buckets; no IP/UA/device or hash, viewer key, proof id, route, exact time, or exact dwell is stored. The final migration drops sys_visit_log; admin route/search/not-found rollups are cleared and no longer returned, and uniqueViewerKeyEstimate remains 0. Same article/epoch Redis dedup is at most 20 minutes and is cryptographically invalidated on independent-key rotation; cross-article/epoch digests differ. Low-sample region/dwell release uses k=10 and fixed UTC-day DP noise with `ε=0.5` per scope and `ε=1.0` total for two scopes. HumanReadProof:Mode=paused stops count writes only; this proof improves the human-read metric but is not authentication and does not detect every automation.

## Authoring, comments, subscriptions, and telemetry

The authoring extension host has a separate internal/experimental default-deny
manifest and signed package boundary. Its closed capabilities are requests only;
verified content-addressed staging and atomic package activation grant no document,
network, filesystem, database, DOM, process, or host-private authority. Hybrid
resolution rejects non-active packages, third-party in-process execution, module
digest drift, and platform fallback; the production trusted-adapter registry is
empty. Third-party pure-compute modules have a verified Wasm-only Linux bubblewrap
path with closed copied messages and no imports, network, filesystem, DOM, process,
database, shared memory, or recursive workers. This adds no HTTP/AEDS or stable
Shared ABI. Verified services run only in an owned bounded process tree and reach
network/files only through exact opaque host grants. See
[Authoring extension capability and isolation boundary](security/authoring-extension-capability-isolation.md).

Plugin manifests request but do not grant access. The closed typed capability catalog defaults to an empty grant; Sensitive capabilities require explicit administrator confirmation and must be a subset of the signed manifest. database.raw, raw filesystem/network, process, reflection, assembly loading, IServiceProvider, unrestricted CLR, and network.unrestricted are not grantable. Each Host API call rechecks its grant. Level 1 JavaScript/Lua disables CLR import and enforces timeout, memory, instruction, call-depth, output, log, and cancellation budgets; Lua is limited to `string/table/math/utf8`, login hooks require `user.auth.hook`, and `cluster-once`/`scheduled`/`leased` hooks require idempotency and fencing. Jint runs with `AllowClr` disabled. Degraded/Quarantined recovery requires administrator confirmation. Use [Plugin permission and sandbox boundary](security/plugin-sandbox.md), [Controlled Lua plugin runtime](architecture/lua-plugin-runtime.md), [Plugin Hook Dispatcher](architecture/plugin-hook-dispatcher.md), and [TypeScript plugin SDK and Jint runtime](plugins/typescript-sdk.md) for the full domain contract. No concrete Lua engine is currently in the dependency graph, so the default adapter fails closed.

Subscription ownership uses only the hmac-v1 identity derived from Subscription:EmailHashPepper. Runtime rejects sha256-legacy, OR fallback, and LegacySha256EmailHash; finalize isolates legacy rows and requires zero remain. Cutover problems pause subscription mutation and use an isolated recovery database. site_subscription stores only HMAC-SHA256(normalizedEmail), hash_version, channel, enabled state, and unsubscribe time; it stores no email or profile. Public unsubscribe needs X-Fsus-Subscription-Proof bound to the keyed hash/channel and a TTL: non-consuming validation precedes the successful DB update and one-use consumption, so timeout/cancel/transaction failure may retry the same proof. Missing/replay/expired/mismatch returns 428. The default implementation has no SMTP, third-party mail, or Web Push provider; an external mail domain may receive only this service's opaque proof over TLS, keeps proof nonce/traceId audit, and never sends clear email back. RSS/Atom/JSON Feed is primary; channel=email is only explicit preference until a provider gate, unsubscribe smoke, and review exist.

All `/api/binary/author/**` routes require an independent admin principal and declared `AdminPermissions.*`: article.write covers drafts/previews/revisions/assets/import-export/AI; comment.moderate covers the queue; anonymous.comment.configure, anonymous.nullifier.block, and anonymous.credential.revoke cover anonymous governance; audit.read covers audit; system.config covers runtime/cache/integrity operations. External /api/author/** JSON and internal bridge are removed.

Server drafts are uniquely ownerAdminPrincipalId+draftKey and are the durable cross-device authority. The browser journal fsusblog-article-recovery-journal is only an unconfirmed window in IndexedDB; there is no fsus:article-draft:* localStorage owner/full-text fallback. fsusblog.article-recovery-journal.v2 binds one-way admin identity, article scope, tab ownership, base/server/client revisions, and source hash. Payload is deterministic utf8-v1 typed plaintext bytes; raw content string is absent. Logical body and stored payload are each at most 1 MiB; TTL is 168 hours; one identity/article has at most eight tab versions and the browser at most 32 records/4 MiB. One writer keeps one in-flight and one newest pending snapshot; rapid input replaces intermediate state and lifecycle flushes request the same owner. Unknown/old schema, unsupported codec, corruption, expiry, hash/byte mismatch, or cap overflow is deleted on read, not migrated. SHA-256 is a one-way identity/source digest only and is not at-rest encryption. Server acknowledgement deletes only an exact client revision/source-hash match, never newer input. Publish/delete/discard, admin/account logout, switch, expiry, privacy cleanup, and shared-device cleanup delete the journal. IndexedDB/private-mode/quota failure only gives a quiet notice; it never falls back to localStorage, extends retention, or overwrites newer server state. ## Audit, retention, and secret recovery

Ordinary audit covers low-risk reads, previews, and operations asynchronously.
High-value audit covers admin/security/audit, investigation hash reads, admin
step-up, PoW/moderation policy, comment visibility, irreversible repairs,
cache/index rebuilds, and public-distribution writes. It synchronously records
source/type/action/outcome/severity/is_high_value/actor/target/trace/path/
method/reason_code and hashed network/device/session values. Admin principal
login/step-up/revoke compatibility audit still uses admin_audit_log through
IAdminAuditLogChannel; bounded queue overflow or batch failure uses synchronous
fallback and queued/dropped/batch/fallback metrics without reducing query
visibility. Audit context never contains credentials, email, username, body,
raw IP/UA, or bare identity IDs. Audit hash/mac/prev_hash remains the chain
when configured.

Detached checkpoints use an independent AuditCheckpointKeyRecord ECDSA P-256 trust domain. Production accepts one current key, absolute .der SPKI/PKCS#8 paths, 0600 private key, output under FSUSBLOG_DATA_ROOT, 30-second to 24-hour cadence, and 1..10000 batch size; current private and historical public-only registry are separate. Workers verify chain/Merkle/range/head before and after append; failure never overwrites old packages, writes an unsigned checkpoint, or reports success. Hot-set Audit:DetachedCheckpoint:Enabled=false to stop creation without restart. Local transport is not WORM; same-host root can delete it, so true deletion resistance requires independent custody, not TSA/S3 Object Lock/public-chain fallback. See [Audit detached checkpoints](security/audit-detached-checkpoints.md).

AuditRetentionCatalog gives every action finite full/pseudonym/aggregate ages, anchor/legal-hold rules, and a cryptographic-erasure key domain; unknown actions fail at write and CI. Sensitive payload uses a retention-epoch AES-256-GCM envelope and an owner-only audit-retention/epoch-keys DEK store, never the site backup. Expiry orders identity-free anchor, signed destruction evidence, DEK destruction, and fenced ciphertext deletion; high-value/Critical cannot bypass it. Legal hold is off by default, limited to catalog-approved actions with purpose, approval, and no more than 30 days; anonymous issuance cannot be held. Investigation requires audit.investigate, purpose, trusted origin, consumed step-up, at most 200 rows, and no raw bulk export. Rollback pauses cleanup but never restores raw payload, skips anchor, or retains DEKs forever. See [Audit retention and cryptographic erasure](security/audit-retention-cryptographic-erasure.md).

Data Protection appends keys and encrypts every XML key with the independent X.509 protector; `data-protection-keyring.tar.gz` never includes the certificate private key; old keys/certificates are removed only after cookie, pending-MFA, recovery, and previous-certificate windows expire. ## Comment author-management capability

Strong-anonymous comment management uses a separate 256-bit capability. The server stores only its SHA-256 commitment; capability and one-use challenge never enter URL, logs, cache keys, localStorage, telemetry, or any account/credential/nullifier mapping. The challenge binds comment id and edit/delete/status/appeal purpose, expires in five minutes, and is consumed once by database CAS under fixed_ip limiting. Forged/replayed/cross-comment challenges fail uniformly without comment-existence disclosure. Lost capabilities cannot recover; the client is told after submit. Admin can read full revision history; anonymous/public readers see only current visible text and edited bit. Tightening Comments:AuthorEditWindowMinutes blocks new history edits without restart and leaves deletion/status/appeal/public read/notification/admin moderation unchanged. Migration adds nullable/defaulted columns and a new table; old clients continue reading existing comment POD.

Report credentials and author capabilities are separate. A report credential uses HMAC with Moderation:ReportPepper, or Moderation:Pepper when unset, plus comment id, only for same-comment deduplication. Raw credential/IP/anonymous proof are excluded from report/event/audit/telemetry. Dynamic rate limiting can close anonymous reports without restart while account reports and moderation reads remain. An appeal proves current author control, binds the latest Hidden/Rejected event, and is unique per decision. The default Moderation:Appeals:RequireDifferentReviewer=true prevents the original reviewer from deciding the appeal. Reload can reject new appeal decisions but retains timeline/report reads; existing events are never deleted or rewritten. Article-level comment override can only tighten the site author-mode switch. Ticket and final submit reread the site -> article -> thread snapshot; a thread lock blocks only new replies under that root, not existing comments or other threads. Slow mode uses a privacy-safe moderation subject hash and CAS inside the comment transaction; it never uses raw IP, device, commitment, nullifier, or reversible account identity. Policy changes require permission, step-up, optimistic version, and append-only comment_policy_audit_event.

## Cluster membership diagnostics

Cluster diagnostics are private operational metadata. Only an independent admin principal with system.config may call GET /api/ops/cluster/nodes; it uses fixed_ip and no-store. Normal users, legacy user-admin roles, anonymous requests, and an admin lacking the exact permission are rejected. The scheduler graph exposes only stable responsibility/capability IDs, replica/node placement, bounded score/reason, assignment time, and an optional fencing token, never lease IDs, Redis keys, queue payloads, module requests, Cookie, token, session, address, connection string, exception, or secret.

Heartbeat proves liveness, not write authority. Only the current resource lease and monotonically increasing fencing token authorize checkpoint/terminal writes; renew/release require the original `leaseId + token`, and stale nodes cannot complete, retry, dead-letter, or compensate after takeover. Idempotency stores only task/object/operation identity, execution state, bounded checkpoint, result digest, low-sensitivity failure code, node ID, and lease metadata; no Cookie/Bearer/MFA/RiskControl proof, IP, device fingerprint, anonymous witness, or credential material. State-control storage failure never disables auth, authorization, PoW, RiskControl, binary framing, or notification admission: multi-node workers stop new stateful writes until Redis recovers or another healthy lease holder exists. Drain the node without restart; never switch to in-memory state or reset fences. Redis records use scoped stable capability IDs and bounded health/load/resource hints; Draining and Maintenance survive failure detection. Removing responsibilities and marking those states stops scheduling while binary routes and notification stream continue.

## Plugin admin authorization and disclosure

Plugin administration is not a new authorization plane. Read/write requires independent admin principal, system.config, fixed_ip, and no-store; install, grant, revoke, start/stop, reload, isolate, recover, uninstall, and config writes also consume one-use admin step-up. Installation additionally requires X-Fsus-Plugin-Confirm: install; isolate/recover/uninstall require confirmed=true in the request. The browser displays only server-generated PluginPermissionPlan. Dangerous/Trusted are not automatic grants; unknown capabilities, raw database/filesystem/network, undeclared manifest requests, and unconfirmed Sensitive requests fail closed.

Plugin logs/errors are isolated by plugin/node/hook/trace and limited by both entry count and log-byte budget. The control plane never returns package bytes, signatures, an unredacted manifest, credential, Cookie/JWT/Passkey, raw header, or exception message. Grant revocation takes effect at the next Host API demand; isolation unloads hooks, clears grants, and cancels later runtime calls without restart or loosening PoW, X-Fsus-*, notification, or AEDS error boundaries.
