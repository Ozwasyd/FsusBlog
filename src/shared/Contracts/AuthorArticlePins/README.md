# Article pin transport source

This source maps the original authenticated `IAuthorArticlePinApplicationFacade`
Read/Add/Remove/Reorder/RevalidateOpen operations. `AuthorArticlePinTransport`
checks the actual request principal, session, site and permissions before and after
awaits. Requests never carry actor/site grants. Read preserves the one original
permission-filtered page, server order, opaque cursor, status, references and actual
receipt. Writes consume original CAS/idempotency receipts; open revalidation emits
no open, tab, session or admission command.

The original owner and supplier references remain immutable. This is source for
#2311/#2312 consumption by #2313, not complete UI, native or runtime acceptance.
All original persistence, permission, projection, facade and DI owners are retained.
No fixture, frozen schema/catalog, golden output or qualification receipt is edited.

## Intrinsic input contract

- SchemaVersion is 1. RequestId is a nonempty Guid, never regenerated by transport.
- Read takes limit1..256 (consumer default64), optional opaque cursor max2048,
  optional nonnegative Int64 expected collection revision and original expected
  article/permission/site/session references max256.
- Add and Remove share ArticleId>0, nonnegative Int64 expected revision and RequestId.
- Reorder captures one 1..64 positive unique-ID plan and optional positive after-anchor
  outside the moved set. The original writer remains the sole ordering authority.
- RevalidateOpen takes ArticleId, nonnegative collection revision and all six original
  nonempty references. PermissionReference is passed to the original facade; Current
  is not synthesized from a display hint.
- Shared response records preserve all original numeric statuses, Guid and Int64
  values, UTC DateTime values, status/reason/digests and receipts. Projection status
  0/1/2/3 means original Current/Stale/Unavailable/InvalidCursor; open status
  0/1/2/3 means original Current/Stale/Denied/Unavailable. Article status 0..4 is
  the original Server enum; deleted items cannot be exported as current pin items.
  These numeric fields are transport data, not a second status/query authority.

## Remaining canonical protocol boundary

The sole frame source is `src/shared/Contracts/Validation/aeds-protocol.json`.
Its existing producer `tools/frontend/generate-aeds-protocol.mjs` owns both C#
frame enums, Shared header, TS frame and C++ frame header. A real pin payload
producer must bind Shared shapes and original enum owners and generate POD/C++/TS
consumers through the original decoder path. Never hand-fill these outputs or use
an unregistered numeric cast, generic JSON frame, assumed child URL or reply stub.

The current source checkpoint supplies no active route/frame IDs or codecs.
Registration/generation scope is awaiting the coordinating owner's explicit HOLD
boundary resolution. The authenticated HTTP route and transport caller remain
blocked until that exact source step is released and the canonical parity source
exists. A collocated contract or successful source check is not an HTTP receipt.
Production activation, runtime/tests/discovery/import/security/privacy workloads,
frozen schemas/catalogs/fixtures/receipts and qualification remain HOLD.
