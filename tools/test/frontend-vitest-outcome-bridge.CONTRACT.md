# Frontend Vitest held outcome bridge

Status: current source contract. Owner: frontend outcome boundary, issue #2651.

`prepareFrontendVitestOutcomeRun` consumes selected tracked test/config files from the actual Git HEAD. It calls the original TypeScript AST adapter and Vitest `collect`, binds native registration locations to closed source declarations, and seals the manifest/replay command before assertions run. Locations, native task IDs and display titles are locators, never semantic identities. Declaration/assertion identities hash comment-free structural source; closed parameter case identities hash literal row data. Duplicate semantic declarations or ambiguous parameter display bindings refuse admission. Dynamic tables, expression callbacks, conditional/nested assertions and uncovered assertions are unsupported proof boundaries, not passing empty evidence.

The caller supplies independently verified source/worktree/envelope/temporal/build/toolchain/policy identities and a seed. Preparation does not qualify those identities. Selected Git blobs, original AST report, executable, bridge/observer modules and native package version are held and rechecked; this local holding does not replace complete runtime source/toolchain closure or entropy authority.

`captureFrontendVitestNativeMaterial` calls the original Vitest `start` API with the original config and selection. The runner subclass reads existing native assertion state without replacing assertions, matchers or hooks. Its `onTaskFinished` callback captures assertion count, raw result and original retry/repeat counters before cleanup; `onAfterRetryTask` captures the terminal state before Vitest replaces a dynamic-skip result or begins another execution. Every execution retains both snapshots and the original cumulative errors. An error offset distinguishes newly raised errors from inherited retry errors without deleting either. The reporter retains native collection, readiness, terminal results and run end in a flushed digest-chained journal, alongside the original JSON reporter bytes. Static skip/todo readiness is distinguished from actual execution. Concurrent assertion state retains an explicit binding gap. Coverage-enabled runs refuse until the existing coverage owner supplies a binding capability; non-applicable coverage and semantic artifacts are explicitly empty.

`harvestFrontendVitestNativeMaterial` retains completed cases and planned started/never-started blocked topology after an actual process interruption. A missing run end requires caller-held actual process outcome. For supported direct callback assertions, the original Vitest structured stack parser locates native failures within source-owned assertion spans; real callback counts separate the executed prefix from the blocked failure tail or skipped remainder. These per-execution observations retain the first failure even if a later native result passes. Unbound locations/counters remain explicit. No message search supplies a canonical failure kind. Prefix assertion success on a killed worker cannot be inferred from readiness alone. All native/prepared/material records have `qualificationEligible: false`; the frozen adapter still requires a separately reviewed failed-tail/dynamic-skip admission contract and independently verified runtime authority.

`runFrontendVitestOutcomeAttempts` delegates process execution, retry policy, authority verification and artifact custody to the existing attempt owner. It preserves the selected test IDs and refuses crossed producer/run/source/worktree identities. The caller must provide the actual independent external authority verifier and explicit environment. This source does not create external envelope or temporal receipts.

`bindFrontendVitestHeldOutcome` requires independently held preparation/material digests, the original aggregate validator, mandatory independent authority/artifact callbacks and actual attempt artifact root. It verifies exact raw file digests against the receipt, reloads material bytes and rederives it from the real journal/report, and checks actual command and executed/failed memberships. Only an eligible clean first attempt with complete supported native binding can reach the frozen candidate-v1 adapter. The adapter owns final validation, skip refusal as successful correctness, canonical outcome/failure taxonomy and exact sets. This bridge computes neither fingerprint nor aggregate and edits no registry/profile.

The ordinary reporter cases execute real Vitest callbacks on isolated Git sources: a failed assertion with an unexecuted tail, dynamic skip after an assertion, and a native retry that retains its first failure and counters. They create no attempt or external-authority receipts and establish collection behavior only. Earlier bridge controls remain bound to their original source and are outside this ordinary reporter verification lane.

The canonical frontend profile is available in the existing `outcome-adapter-catalog.json` through `readOutcomeAdapterCatalog` and `validateOutcomeAdapterCandidateData` from owner capability `3f6f443ac4e253f7a9b80e7c7c910d2de8fce824` (PR3998). It preserves the frozen adapter source `fc3c3499a843917d31805a136efedd04fffcc61b`. Actual-file custody remains with the existing `outcome-input-custody.mjs` interface. This bridge introduces no registry or substitute custody verifier. Canonical failure classification, coverage-source binding, independently held adapter review and physical envelope/temporal qualification remain separate acceptance conditions.
