# Frontend Vitest held outcome bridge

Status: current source contract. Owner: frontend outcome boundary, issue #2651.

`prepareFrontendVitestOutcomeRun` consumes selected tracked test/config files from the actual Git HEAD. It calls the original TypeScript AST adapter and Vitest `collect`, binds native registration locations to closed source declarations, and seals the manifest/replay command before assertions run. Locations, native task IDs and display titles are locators, never semantic identities. Declaration/assertion identities hash comment-free structural source; closed parameter case identities hash literal row data. Duplicate semantic declarations or ambiguous parameter display bindings refuse admission. Dynamic tables, expression callbacks, conditional/nested assertions and uncovered assertions are unsupported proof boundaries, not passing empty evidence.

The caller supplies independently verified source/worktree/envelope/temporal/build/toolchain/policy identities and a seed. Preparation does not qualify those identities. Selected Git blobs, original AST report, executable, bridge/observer modules and native package version are held and rechecked; this local holding does not replace complete runtime source/toolchain closure or entropy authority.

`captureFrontendVitestNativeMaterial` calls the original Vitest `start` API with the original config and selection. The runner subclass reads existing native assertion state without replacing assertions, matchers or hooks. The reporter retains native collection, readiness, terminal results and run end in a flushed digest-chained journal, alongside the original JSON reporter bytes. Static skip/todo readiness is distinguished from actual execution. Concurrent assertion state and dynamic skip after execution retain explicit binding gaps. Coverage-enabled runs refuse until the existing coverage owner supplies a binding capability; non-applicable coverage and semantic artifacts are explicitly empty.

`harvestFrontendVitestNativeMaterial` retains completed cases and planned started/never-started blocked topology after an actual process interruption. A missing run end requires caller-held actual process outcome. Raw error objects, planned assertion identities and observed native assertion counts survive failure; failed assertion location/classification and the blocked assertion tail remain explicitly unsupported for candidate admission. No message search classifies failures. Prefix assertion success on a killed worker cannot be inferred from readiness alone. All native/prepared/material records have `qualificationEligible: false`.

`runFrontendVitestOutcomeAttempts` delegates process execution, retry policy, authority verification and artifact custody to the existing attempt owner. It preserves the selected test IDs and refuses crossed producer/run/source/worktree identities. The caller must provide the actual independent external authority verifier and explicit environment. This source does not create external envelope or temporal receipts.

`bindFrontendVitestHeldOutcome` requires independently held preparation/material digests, the original aggregate validator, mandatory independent authority/artifact callbacks and actual attempt artifact root. It verifies exact raw file digests against the receipt, reloads material bytes and rederives it from the real journal/report, and checks actual command and executed/failed memberships. Only an eligible clean first attempt with complete supported native binding can reach the frozen candidate-v1 adapter. The adapter owns final validation, skip refusal as successful correctness, canonical outcome/failure taxonomy and exact sets. This bridge computes neither fingerprint nor aggregate and edits no registry/profile.

Controlled tests execute real native processes on isolated Git fixtures, including duplicate display titles, literal rows, assertion failure, skip, mutation and a real timeout. Their authority callbacks are explicitly controlled test data. These checks establish source contracts; they do not establish native production qualification. Actual consumer integration still needs the canonical frontend profile/catalog and independently verified runtime envelope/temporal material. The frozen adapter cannot currently consume a failed test's blocked assertion tail or a dynamically skipped test's already-executed membership; its owner must review that narrow contract extension separately.
